## Project overview

**Traffic and Dragons** is a browser-based sword & sorcery RPG. The player creates a character through a multi-step wizard, then plays a text adventure narrated by Claude (via the Anthropic API) acting as the Game Master. The GM responds in vivid second-person prose, tracks the world state through hidden tags embedded in its responses, and maintains a rolling memory of NPCs, locations, lore, and decisions across sessions.

There is no build step and no npm dependencies. There is a cloud sync server on Fly.dev (`https://traffic-and-dragons-server.fly.dev`) — optional, used for cross-device campaign persistence.

**This file holds current contracts only.** Version-by-version evolution, incident stories, and measured evidence live in [DOC/CLAUDE_HISTORY.md](DOC/CLAUDE_HISTORY.md) — when a contract here earns a war story, the story goes there and the contract line links to it.

## Conventions

- **ES5.1+ JavaScript** — `var`, no arrow functions, no template literals, no `const`/`let`. `async/await` where a function awaits I/O (model calls, sync, storage, audio); `dev/check-es5.js` polices the forbidden forms (const/let, arrows, template literals, classes). ES5.1 builtins (`.forEach`, `.map`, `.filter`, `Object.keys`) and `Object.assign` (ES6, universally supported) are permitted.
- **Single-character variables** common in dense utility functions.
- **HTML built by string concatenation** — no templating engine.
- **State versioning via key suffix** — every storage key carries its OWN `_vN`, bumped when that key's shape changes: the three state objects are at `_v10`, the rules at `_v9`, nearly everything else at `_v1`. The full list is generated into [sync.md ▸ 3. State management](DOC/contracts/sync.md) by `dev/storage-keys.js` and checked by run-tests (#523).
- **No front-end dependencies** — CSS and JS entirely self-contained.
- **CSS variables** for theming — palette in index.html's `:root`; **satellites link `satellite.css` (#312) and define no tokens of their own** — one palette across the game, the home page, the reference and the editors (the SATELLITE PALETTE CONTRACT in run-tests pins it). **#481 G5:** EVERY tracked root page links satellite.css or carries a reasoned `EXEMPT.palette` entry in `dev/class-guards.js` (index.html is the palette's source); every tracked root page outside APP_SHELL must match sw.js's network-first regex — both derived from the tree, not a list. Accent `--acc` is the visual identity color.
- **Modals always created fresh** — remove prior instance by ID before creating new one. **Focus (#442, #481 F3):** `modalShell` moves focus into the dialog, contains Tab and restores the opener on close. A same-id re-creation (an in-place re-render) inherits the first opener and disconnects the old dialog's removal observer. A restore acts only when focus was lost, and never behind an open dialog. Code hands the keyboard back to the story box only through `focusStoryBox()` (ui-shell.js), which yields while a dialog is open — so Enter can never send a turn from behind a popup.
- **Every in-flight status line counts elapsed seconds (owner rule 2026-09-06, #356).** Any status that waits on a model or an image ("Generating…", "Reading…", the loading modal) rides `elapsedTicker(el,base,opts)` (helpers.js): it paints `<base> Ns`, `set()` swaps the base while the clock runs, `stop()` runs BEFORE any terminal text is written. A frozen status reads as broken long before it reads as slow. **Derived since #481 G5:** `dev/class-guards.js` finds every ellipsis status painted in a function whose flow waits on `callGM`/`falFetch`/`falQueueRender` (directly or through a top-level helper; deferred handlers excluded) — a new frozen wait fails the suite wherever it lands; a deliberate non-status goes in `EXEMPT.paints` with its reason. One status per wait: the designer's sticky statusline rides `statusTicker(base)`; a modal's button ticks when the modal covers the line; a batch owns ONE ticker. **Helper-painted waits count too (owner ruling 2026-09-30):** `addMsg` ticks every story thinking marker ("The world turns... 7s"; change its words only through `setThinking` — the guard finds a direct write), and `_carSetStatus` ticks the Car Mode waits declared in `CAR_WAIT_STR` (thinking, retrying, getting options, transcribing).
- **`busy` flag** — global boolean gates all API calls. Always set `busy=false` in both success and error paths.
- **The top inset (#658).** Every top-docked surface clears `var(--top-inset)` (index.html `:root`, 1.7 × `env(safe-area-inset-top)`), never `env()` directly: since iOS 26.1 a Home Screen web app's status-bar glass blurs ~40pt below the bar and nothing switches it off; the #658 test derives the rule from every root page and stylesheet.
- **Scrollbars** — custom styled via `::-webkit-scrollbar` rules: 6px wide, near-black track, dark grey thumb, amber on hover.
- **Opposing values never share a stem (owner rule 2026-09-04).** When two values of one field are opposites, pick words with no common substring — `peaceful`/`violent`, never `nonviolent`/`violent`; `known`/`unknown`, `active`/`inactive`, `dead`/`undead` are the same trap. Every substring or prefix test on the value is otherwise a latent misfile (the #330 kind classifier found it once). Exact equality is the only safe test on a pair that does share a stem.
- **No pill/chip borders on non-interactive elements** — use plain text, comma-separation, or `cs-list-row` rows instead. Borders imply clickability. ONE sanctioned exception: the verdict-badge standard below, for doc/satellite pages only.
- **Verdict/status badge standard (user-approved 2026-07-12)** — doc/satellite pages needing a colored verdict badge use the muted-fill pill (`.lean`, DOC/Research/app_vs_browser.html): background = the accent cut to 20% of its HSV value (`#7aa86a` → `#182215`), 1px full-brightness accent border (the rim carries the color), bold monospace uppercase text at `rgba(255,255,255,.4)`, `border-radius:12px; padding:2px 10px; font-size:.78em; letter-spacing:1px`. Game-UI surfaces keep the no-pill rule above.
- **`DOC/` holds reference docs; audits live in `audits/`; satellite TOOLS stay at root; so does the daily working set** (`CLAUDE.md`, `TODO.md`, `todo_checkWithFable.md` — by design; lint-todo hardcodes the path). Sample `.blueprint` fixtures in `samples/`; personal `.tnd` saves in `testRuns/` (gitignored); exported narrative mementos in `momentos/` (gitignored). A file cited by an audit must keep its link working — move the citation in the same commit. **#481 G8:** every relative link in CLAUDE.md and `DOC/contracts/*.md` is checked by `dev/check-doc-links.js` (file + `#fragment`, GitHub slugs keep `_`); run-tests fails on a dead one.   2. **Prove every contract clause with `dev/sabotage.js`, and treat a mutation that changes no bytes as a FAILURE.** A green clause guarding nothing is worse than no clause. The harness restores the file on exit, crash and Ctrl-C, and asserts byte-identical restoration. **A `find` that matches more than once is refused too (2026-09-21):** the harness mutates the FIRST match, so a same-worded line landing earlier in the file silently moves the mutation to the wrong site while the guard stays green — `dev/check-sabotage-applicability.js` (the CI gate's dry scan) fails an ambiguous anchor; anchor every clause on a unique span. **A clause may run its own test (2026-11-06):** a group's `only: "<mustFail prefix>"` turns each clause's `mustFail` past the prefix into the guarded suite's `--only <test name>` argument, and a clause may carry a `command` of its own; a suite answers a filter that names nothing with `matched 0 tests` and exits red, which the harness reads as UNOBSERVED — the atlas batteries went from 26 minutes to about one this way. Found when a village-stash clause had been mutating `fileLayout` instead of `fileLocationItem` for a week, hiding a second false proof behind it (a battery stops at its first failing group — a MISSED clause can mask the ones after it).
  3. **`dev/file-forensics.js <file>` before the second theory.** One command prints every file-level fact (size, times, encoding, parses-or-not, git state, temp siblings, write-lock) and exits non-zero on anomalies. When an error asserts a fact, verify it exhaustively before reinterpreting it.
  4. **The bible workflow is SERVER-FIRST (#72 overhaul, 2026-08-14 — the fill-phase-languish diagnosis):** run `node dev/bible-server.js`, then every editor save (class Save, capability Add/Update) is one-click — validated by install-bible, written by node, no FSA ceremony, and NO TOKEN for locally-served pages (origin allow-list; the per-run token survives only for file:// pages). ## Dev workflow

**Running locally:**
1. Open `index.html` directly in any modern browser (Chrome, Firefox, Edge). A page opened as a local file has no live dice and no ambience (the browser refuses their files there; each says so once) — serve the folder for those: `node dev/static-server.js`, then http://localhost:8123/.
2. Enter your Anthropic API key (`sk-ant-...`) on the opening screen.
3. The key is stored in `localStorage` under `tnd_ak_v1` and auto-loaded on subsequent visits.
4. No build step, no `npm install`.

**Diagnosis & verification discipline** (origin sagas in [history](DOC/CLAUDE_HISTORY.md#the-v027v028-textarea-saga-origin-of-the-diagnosis-discipline)):
- **Verify the FAILURE condition, not a benign case.** A check that can't fail proves nothing — exercise the input that would break it: overflow, empty, boundary, the exact thing reported.
- **For visual/layout work the screenshot is ground truth; measurements are a proxy.** When they disagree, believe the render and find why the number lied. Don't let a passing metric override the eye.
- **"Measures fixed but reported still broken" → reproduce before explaining.** The gap is the clue; "cache/environment" is never the first explanation for a divergence you haven't reproduced. A user's "confirm it visually" is usually correct — honor it.
- **Test-first on engine changes** — the failing assertion defines and exercises the break before shipping. Headless tests can't see CSS layout, so a visual bug's test-first equivalent is a scripted preview that sets up the edge case AND screenshots it.
