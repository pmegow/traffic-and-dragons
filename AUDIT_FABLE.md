# Traffic and Dragons — AUDIT (Fable)

Audit of the full project at v1.143 (2026-07-01). Notes and suggested remedies only — nothing was changed. Scope: inefficiencies, drift vulnerabilities (narrative inspiration + story/state), and general kruft. Read HANDOFF.md and TODO.md first; findings already tracked there are referenced, not duplicated.

## Drift — narrative inspiration (prose voice)

| # | Task | Effort | Status |
|---|---|:---:|---|
| 1 | **Prose author silently dropped by three creation paths.** `startGame()` (game.js:14) only stores the author when called with 4 arguments, but `showCreationSpellPick` early-exit (char-creation.js:352), `confirmCreationSpells` (char-creation.js:395), and `cbConfirm` (char-creation.js:479) all call `startGame(c,pendingTone,pendingVoice)` — 3 args. So ANY caster (goes through the spell picker) and ANY level ≥4 start (goes through stat bumps) loses the author picked in Step 1; the campaign silently inherits the device default from `PROSE_K`, which may be a different voice or none. Only the no-spells/no-bumps paths (char-creation.js:299, :334) pass `pendingAuthor`. This is a direct "the author's voice evaporated" vector that no prompt tuning can fix. **Remedy:** pass `pendingAuthor` at all four call sites — or more robustly, drop the `arguments.length` check and have `startGame` read `pendingAuthor` itself so the bug class can't recur. Also note `_startImportedCampaign` (ui.js:2008) passes 3 args by design (import flow has no author picker) — if that's meant to inherit the device default, make it explicit with a comment or a 4th arg. | S | Pending |
| 2 | **Tone voice and author voice are two competing style directives.** `buildSysPrompt` injects the TONE block (`tone.voice`, e.g. "Write with pulpy energy…", api.js:69) AND the STYLE block with the author `vc` (api.js:209). Both are style instructions; the model averages them, diluting the author voice — the same failure mode old TODO #27 ("voice mostly evaporated by turn 32") was about. The STYLE block says "never blend with a neutral GM voice" but says nothing about the tone directive it just read. **Remedy:** when a prose author is set, strip the style clauses from the tone block (keep tone as a CONTENT directive: magic prevalence, violence register, stakes) or explicitly subordinate it: "TONE governs content; the VOICE below overrides all style guidance." | S | Pending |
| 3 | **`summarize()` reads only the first 300 chars of each message.** memory.js:245 slices every sessionLog entry to 300 chars before extraction — a 1,000-token GM turn is ~4,000 chars, so the extractor sees ~7% of each scene, always the opening. Chapter summaries, NPC knowledge, decisions, and future events are extracted from scene openings only; anything that happens mid/late scene silently never enters long-term memory (a slow, invisible story-drift engine). The 2,000-token budget is on OUTPUT; input is not the constraint. **Remedy:** raise the slice substantially (e.g. 1,500–2,500 chars, or full GM messages + trimmed player messages), and verify cost per summarize is still acceptable (~1 per 1,200 session tokens). | S | Pending |
| 4 | **Action-suggestion call has zero character context — root cause of Known issue #4.** `generateActions` (game.js:49) uses a bare `sysOverride` ("You suggest player actions…") with no character sheet, so the model invents actions from prose alone — "Cast Magic Missile" for a character who doesn't have it. The GM then correctly refuses, but the button should never have rendered. **Remedy:** append a one-line sheet digest to the override (class, HP, available spells, key abilities, notable inventory) — ~50 tokens buys sheet-legal suggestions. Cross-reference: TODO Known issues #4. | S | Pending |

## Drift — story/state desync

| # | Task | Effort | Status |
|---|---|:---:|---|
| 5 | **A failed `summarize()` permanently destroys the session log.** memory.js:255 catch block does `sessionLog=[]` — one bad JSON parse or network blip discards up to ~1,200 tokens of unarchived events from long-term memory forever (eventHistory only gets a "Summarisation failed" marker). The GM's future context loses that whole chapter. **Remedy:** on failure, KEEP sessionLog and retry on the next turn; add a failure counter so 2–3 consecutive failures fall back to archiving the raw (truncated) text as the chapter summary instead of dropping it. | S | Pending |
| 6 | **`summarize()` NPC updates bypass `resolveNpcName` — re-opens the v1.143 fork fix.** memory.js:250 writes `memory.npcs[nu.name]` directly from extractor output; the extractor freely returns variants ("Morwen (Ammut's wife)", "Sheriff Hemlock"), forking NPCs exactly the way the v1.143 `resolveNpcName` rewrite prevents for tags. Entries are also created without `aliases:[]` (shape drift). Since summarize runs every ~1,200 tokens, this is a steady fork source. **Remedy:** `nu.name = resolveNpcName(nu.name)` before writing, and create entries via one shared blank-NPC factory (see #17). | S | Pending |
| 7 | **`[XP:+25]` is silently swallowed.** The XP parser (api.js:345) requires `\[XP:(\d+)\]` — no sign — while the GOLD/HP formats explicitly use signed values, inviting models (especially non-Claude) to write `[XP:+25]`. `cleanTxt` strips the unparsed tag from display, so the award vanishes with no visible symptom: prose says "you gain experience," sheet never moves. Same gap in `[COMPANION_XP:Name\|N]` (api.js:447). **Remedy:** loosen both regexes to `\[XP:\s*\+?(\d+)` (mirroring the v1.32 GOLD/HP loosening); consider the same tolerance pass over other numeric tags. | S | Pending |
| 8 | **Blueprint-seeded locations crash `fileLocation` on first travel.** `applyBlueprint` (game.js:301) seeds `memory.locations[name]={visits:0,notes:[]}` but `fileLocation` (memory.js:62) unconditionally runs `memory.locations[loc].visited.push(turn)` — `.visited` is undefined on seeded entries → TypeError inside `applyMuts` the first time the GM emits `[LOCATION:]` for a seeded location (e.g. Sandpoint in the Runelords blueprint). The exception aborts ALL remaining tag processing for that response (caught by sendAction as "GM error"), desyncing everything the response contained. **Remedy:** seed with `{visited:[],notes:[]}` AND make `fileLocation` defensive (`if(!memory.locations[loc].visited)memory.locations[loc].visited=[];`). | S | Pending |
| 9 | **Re-roll and retry desync the transcript (story compiler's source of truth).** `rerollLast` (game.js:213) swaps the displayed narration and sessionLog entry but never touches `worldState.transcript` — the keepsake record keeps the discarded scene and lacks the one the player actually read. `retryLast` (game.js:208) re-runs `sendAction`, which re-renders AND re-logs the player line (game.js:182), so a failed-then-retried turn stores the player action twice. **Remedy:** in rerollLast, replace the last `r:"gm"` transcript entry; in sendAction, skip `logTranscript` when the last transcript entry is an identical player line (retry signature). | S | Pending |
| 10 | **"Update & Retry" API-key box writes a key slot that's never read.** `_attachGMErrorUI` (game.js:247) stores the pasted key into `apiKey` + legacy `AKK` only, but `callGM` reads `providerKeys[activeProvider] || apiKey` (api.js:460) — and `providerKeys[activeProvider]` always exists after first setup (submitKey/loadProviderSettings populate it). The stale invalid key keeps winning; retry fails forever no matter what the user pastes. Worse on non-Anthropic providers. **Remedy:** write `providerKeys[activeProvider]=k; saveProviderSettings();` (keep the AKK write for legacy migration only). | S | Pending |
| 11 | **Summarization threshold is three different numbers.** sendAction triggers at ≥1000 (game.js:185), `summarize()` refuses below 1200 (memory.js:239), the membar dot goes red at ≥1000 (ui.js:393), and CLAUDE.md documents 1000. Between 1000–1199 the UI screams red, every turn awaits a summarize() that no-ops, and nothing happens until 1200. **Remedy:** one constant (`SUMMARIZE_AT`) in globals.js consumed by all three sites; align CLAUDE.md §8. | S | Pending |
| 12 | **The "USED NAMES list" rule points at a list that never exists.** DEFAULT_RULES (data.js:149) instructs "NEVER use a name on the USED NAMES list" — but nothing populates `memory.usedNames` (always `[]`, confirmed project-wide grep) and `buildSysPrompt` never injects such a block. Dead rule text burning prompt tokens + a dead state field. Related: `getNameSuggestions(10)` is called INSIDE `buildSysPrompt` (api.js:164) and mutates `memory.nameIdx` — a write side-effect in the prompt builder, so every internal call (sheet sync, re-roll, action gen doesn't but sync does) burns 10 names, and the prompt is never byte-stable, which will sabotage the planned prompt caching (TODO #11). **Remedy:** either implement usedNames (append when an NPC is actually registered; inject the list) or delete the rule sentence + field. Move the nameIdx advance out of the builder — advance only when a suggested name is consumed by a new `[NPC:]`. | M | Pending |
| 13 | **NPC detail injection misses alias mentions.** The hot-NPC scan (api.js:130) substring-matches canonical names against the last 6 messages; an NPC referred to only by alias or short form ("the Sheriff", "Morwen") gets no ACTIVE NPC DETAILS block that turn — the GM improvises from prose momentum instead of recorded knowledge. **Remedy:** match aliases too (`memory.npcs[k].aliases`), and consider matching distinctive tokens from `npcCoreTokens` for short-form mentions. | S | Pending |
| 14 | **Engine doesn't enforce the offered-quest gate it promises.** The rules say an offered quest may never be advanced or auto-accepted, and `buildQuestBlock` repeats it — but `applyMuts` happily applies `[QUEST_STEP:]` to offered quests (api.js:349) and `[QUEST:title\|active]` from the GM with no player agreement check. Prompt-only enforcement, same class of fix the HANDOFF flags as "improve the odds, not guaranteed." **Remedy (backstop):** ignore QUEST_STEP on `status==="offered"`; optionally toast when the GM self-activates a quest so the player notices (full enforcement is impossible — in-story acceptance is legitimate — but the step-gate is free). | S | Pending |
| 15 | **`importSave` skips the loadState migration battery.** ui.js:686-708 assigns `worldState` directly; an older exported save misses the migrations loadState applies (quest `objectives`/`desc`, `transcript`, `campName`, `portraitOffset`, `legacyCharsUsed`, `pendingLegacy`). It self-heals on the next full reload, but the live session in between runs on an unmigrated shape. **Remedy:** extract loadState's migration block into `migrateWorldState(ws)` and call it from both loadState and importSave. | S | Pending |

## Inefficiencies

| # | Task | Effort | Status |
|---|---|:---:|---|
| 16 | **Every turn POSTs the full state to the server 2–3×, including the entire story DOM.** `saveAll()` → `syncToServer()` fires from `applyMuts` (api.js:455) AND from sendAction (game.js:201) each turn, and each POST ships worldState + full memory + sessionLog + `narrativeHtml` = the complete `#story-narrative` innerHTML (storage-adapter.js:199), which grows without bound over a campaign. `_pendingSync` coalesces overlaps but not sequential sends. Late-campaign this is hundreds of KB several times per turn — battery, bandwidth, and Fly ingress for zero benefit. **Remedy:** debounce syncToServer (trailing ~2s so one turn = one POST); cap narrativeHtml to the last N messages — or drop it entirely and rebuild replay from `worldState.transcript` (see #18). | M | Pending |
| 17 | **Action-suggestion call resends the entire session history.** `generateActions` (game.js:49) builds its request from the full sessionLog (up to ~1,200 tokens) to produce 3 short strings with a 200-token budget, every single turn. Only the last exchange is relevant. **Remedy:** pass just the last GM response (or last user+assistant pair) as the message; combines naturally with the sheet-digest fix in #4. Note also generateActions runs after `busy=false`, so a fast next action races it — `worldState.lastActions` can be written after the next turn starts (stale buttons on reload). A cheap guard: discard the result if `worldState.turn` changed since the call started. | S | Pending |
| 18 | **The same prose is stored four ways.** A narrative turn lives in (1) `worldState.transcript` (verbatim, by design), (2) `sessionLog` (raw, until summarize), (3) `narrativeHtml` DOM copy shipped to the server each sync, (4) `eventHistory`/`memory.chapters` (summaries, by design). (3) is fully derivable from (1) and is the largest of the four. **Remedy:** rebuild the story pane from `transcript` on load/device-hop instead of persisting DOM HTML — kills the biggest sync payload and fixes the "DOM-snapshot truncated by reload" caveat noted in TODO #5's decision log. | M | Pending |
| 19 | **DEFAULT_RULES has grown to 28 rules (~1.6k words) re-sent every turn.** Several overlap heavily (4 DRIVE / 5 DANGER / 14 fresh-characters; 17 tight responses / 18 tight prose; 9 never-repeat-lore / 10 never-reuse-detail; 25 QUESTS / 26 ACTIVE CRISES). Long rule lists cost tokens AND dilute per-rule compliance — the v1.143 audit found the NPC-naming rule followed 0/54 turns partly because it's rule 23 of 28. **Remedy:** an editorial merge pass targeting ~18–20 rules with the same coverage; pairs with prompt caching (TODO #11) — the static rules block is the prime cacheable prefix, so do the edit first, then freeze it. | M | Pending |
| 20 | **`buildSysPrompt` rebuilds everything from scratch every call — fine today, but the volatile/stable interleave blocks TODO #11.** Confirmed while auditing: stable content (rules, tag reference, style/voice) is interleaved with per-turn state exactly as TODO #11 describes, and #12's `getNameSuggestions` side-effect makes even the "stable" section unstable. No new remedy — this item exists to link the audit findings (#12, #19) as prerequisites for the caching work. | — | Pending |

## Suggested priority order

1. **#1 (author dropped at creation)** and **#8 (blueprint location crash)** — small, sharp, user-visible bugs.
2. **#5 / #6 / #3 (summarize: log wipe, NPC forking, 300-char truncation)** — the memory pipeline is the story's long-term spine and all three quietly erode it.
3. **#10 (key retry writes dead slot)** and **#7 (signed XP)** — small parser/flow hardening.
4. **#4 + #17 (action generator: add sheet, shrink payload)** — one edit fixes Known issue #4 and cuts cost.
5. **#12 + #19 + #20** — do together as the prelude to prompt caching (TODO #11).
6. **#16 / #18 (sync payload)** — biggest bandwidth win; touches the sync path so test on two devices.
7. Kruft items opportunistically, on-touch, per the coding conventions.
