Sol review of the drift-hardening action plan

Review target: driftHardeningActionplan.html · code/save changes expressly out of scope · 2026-08-11
Verdict: approve the program, but do not execute the plan as written. The incident register is strong and W1 is ready for failing-first implementation. The plan also correctly identifies the need for referential integrity, summary validation, and a two-axis relationship design. However, several proposed detectors are not yet mechanically defined, and several repair recipes would replace observed drift with a new guess. The most serious are the preferred Mokmurian retcon, the blanket re-key of 56 transcript entries, use of an ordinary [NPC:Sable|…] tag for an offstage person, natural-language duration passed to a parser that turns it into one minute, exclusion of companions from NPC memory, and unreceipted direct edits/deletes of derived canon.

This review endorses an item only where the mechanism, authority, and failure condition line up. ENDORSE means the proposed outcome is supported. REVISE means the problem is real but the action needs the stated constraints. REJECT means the action as written is likely to corrupt or erase evidence. DESIGN / MEASURE means no implementation should start until the proposal or corpus gate is complete.

2. Workstream review

W1 — close the Owed hole

ENDORSE This is the only workstream ready to move directly to a failing test. WEIGHTY_REL_RE at globals.js:22 is used by both core-memory filing (game.js:1140) and downgrade detection (game.js:1265); today it matches wed inside Owed. Word boundaries solve the demonstrated substring class.

  • Correct the test narrative: runtime order is snapshot → applyMuts → detectCoreMoments → stampRelationshipChanges, not parser → stamp → core detection (game.js:1392–1404).
  • Make morphology explicit. An outer boundary around widow would stop matching widowed; an exact betray would stop matching betrayed. The legitimate matrix must include the forms the product actually intends: wed/weds/wedded/wedding if intended, wife/wives, widow/widowed, betray/betrayed/betrayal/betraying, lover/lovers, betrothed/betrothal, and the blood-bound forms.
  • Run the exact two t1666 raw tags through the real commit order. Assert both relationship directions, the pending downgrade state, no false bond moment on any of the four witnessing sheets, persistence/re-fire, and pair-scoped resolution.
  • Keep the false lexical cases: owed, showed, midwife, loathes, clover. Add case and punctuation variants.

W2 — referential integrity for high-impact writes

ENDORSE PROPOSAL; REVISE ARCHITECTURE The diagnosis is correct: “known NPC” is not evidence that a named NPC is the corpse. The current summary backstop stamps an extracted death if the name is already on file (memory.js:1231–1241), which creates the exact substitution bias seen with the anonymous scholar and Mokmurian.

The proposal must extend, not parallel, the shipped #156 identity layer. IDENTITY_DOMAINS, provisional NPCs, same/distinct confirmation, and preimage receipts already own stored-entity resolution (identity.js:28, 404–465). W2 adds a different missing concept: the actor occupying a scene role and the evidence linking that actor to a canonical entity.

  • Phase 1 scope: entity-bearing writes only—combat foe creation/death, direct NPC death, identity merge, and summary npcDeaths. Most quests have no entity target, so “gate every quest completion on a present scene entity” is not representable today.
  • Quest/reward scope requires a transaction design. [XP:] mutates and levels the party before the title-keyed quest handler runs; rewards carry no quest id, target, or transaction id (tag_table.js:403–450). Post-hoc rollback is unsafe. A preflight envelope or explicit target/transaction metadata is required before W2 can promise to quarantine the whole bundle.
  • Live and delayed evidence have different lifetimes. A scene ledger that expires on transition cannot validate a later summarization window spanning several scenes. Either stamp compact entity evidence/source turns onto relevant transcript entries, require extraction output to cite that evidence, or keep live mutation gating and delayed summary validation as two coordinated paths.
  • Negative identity must be structured. A free-prose regex for “not Mokmurian” would itself be a recognizer on the hottest mutation path. Prefer an explicit exclusion/claim with source turn; otherwise proposal-first corpus validation is mandatory.
  • Preflight before mutation. applyMutsTable mutates handler by handler and continues after handler errors. Cross-tag quarantine belongs before table execution, not in npcUpsertTarget and not in rollback.
  • Critical overflow fails closed. Keep the narration, retain a visible unresolved item, and quarantine the mutation. A cap overflow must never mean “apply the unverified death anyway.”

The action plan’s broader claim that the anti-drift plumbing is sound should be narrowed to “most shipped write/receipt paths operated as designed.” Known-only death eligibility and unlinked quest/reward tags are themselves load-bearing commit semantics, not merely an unwatched prose boundary.

W6 — summary-commit validation and recurring names

ENDORSE, BUT SPLIT THE TWO HALVES Validation belongs between JSON parse and applySummaryExtract, before deaths, supersessions, facts, lore, decisions, events, or chapter text can mutate. A validator inside fileChapter is too late.

  • Limit canonical identity rows to actors actually present in the extraction window. Distinguish explicit pronoun canon from the UI’s synthetic they/them fallback.
  • Reject only high-confidence contradictions: an explicit structured subject, or one canonical actor with no competing antecedent. Ambiguity should pass with telemetry, never trigger blind replacement.
  • Throw before any mutation so the existing retry path can be reused. Decide separately how validator strikes persist across reloads; today the three-failure counter is process-local.
  • The degraded fallback cannot simply inject raw text known to contain an identity contradiction. Define a visible non-injected archive or memory-gap policy for exhausted identity failures.

The Sable class is a separate registration proposal. Mine deterministic candidates from distinct GM transcript entries and attach evidence turns; exclude existing people, player/party, locations, quests, factions, and capability/item names. Human acceptance should create a minimal memory-only identity without inventing mood, relationship, pronouns, or presence. Do not route acceptance through ordinary [NPC:], which would stamp the current location. Corpus-measure the proper-noun threshold and cap/dedupe both pending and refused candidates.

W7 — two-axis relationships

ENDORSE PROPOSAL WITH AN EXPLICIT WRITE CONTRACT One fixed bond plus one fixed dynamic per resolved pair is bounded and addresses the data model problem. The schema alone does not prevent t1666.

  • Generic/passive relationship updates may change dynamic but may not replace a non-empty bond.
  • Bond creation, redefinition, severance, and removal need an explicit distinct operation and a reversible preimage receipt. If a regex decides the target axis, the Owed/wed class remains part of correctness.
  • Core memories, reciprocity, and the durable graph should use bond; scene rendering can show both. Define removal semantics independently for dynamic, bond, and entire pair.
  • Migrate an old single descriptor losslessly into bond, leaving dynamic empty, unless a human repair classifies it otherwise. Make the migration idempotent across .tnd, .char, live companions, PC switching, legacy injection, and UI/prompt readers.
  • Enforce one canonical pair per resolved entity and descriptor length bounds; no per-change history array. New receipt arrays must ride import/export whitelists.

6. Revised sequence

  1. Export and contain: back up the live campaign; purge the four false defining moments; restore the supported Ammut↔Frizwick bond pair with receipts. Leave Mokmurian unresolved/alive unless the owner explicitly chooses the retcon branch.
  2. Ship W1 alone: exact t1666 replay, morphology matrix, real runtime order, all-green suite, version markers, tracker receipt.
  3. Remove current prompt noise: ship SAY compliance as its own failing-first change after defining deterministic untagged boundaries.
  4. Land low-risk observability separately: tag provenance, non-empty mutation labels, typed bookkeeping receipt, and clock-derived world time.
  5. Repair the remaining W3 recognizers independently: phase splitter/cue scope, stay-behind subject binding/OOC path, then consumable TYPE + owner/use semantics. Do not couple their rollback.
  6. Write the W2/W6 identity-commit proposal: reuse #156; decide live versus delayed evidence, structured exclusions, preflight transaction scope, summary rejection, and exhausted-failure policy. Build only after owner ruling.
  7. Write W7 independently: explicit bond operations, migration/readers/imports, and reversible receipts.
  8. Instrument and corpus-test W4 before implementation: location candidates, journey state/shortfall, accepted commitments/duration normalization, single lifecycle authority, and outcome-aware resolve suggestions.
  9. Run the campaign repair through tested surfaces: pairwise map dry-runs; typed split/allocation for Collector/Savah; minimal offstage Sable registration; per-entry location-index manifest; exact inventory/future-event repairs; archived preimages for every console-only change.
  10. Exit audit: replay exact failures, inspect fresh prompt/state/export, verify no false notes, and compare every repair receipt against its saved preimage.

7. Final position

Endorsed direction: W1, segmentation-aware SAY compliance, item-bible consumable classification, typed receipts/provenance, one clock authority, proposal-first referential integrity, precommit summary validation, and explicit bond/dynamic storage.
Rejected shortcuts: canonizing Mokmurian to preserve downstream state, mass-rekeying a mixed transcript window, turning fuzzy language into scheduler input, excluding companions from memory, registering an offstage NPC through a presence-stamping tag, heuristically equalizing XP, and overwriting/deleting audit evidence without preimages.
Bottom line: the action plan is a good reconciliation document and an unsafe execution script. Incorporating the constraints above turns it into a defensible implementation and repair program.
