The Multiplying Beds — drift analysis at t1431

Campaign: Rise of the Runelords (Ammut) · save Rise_of_the_Runelords__Ammut__Ammut_t1431.tnd · engine v1.540 era (turns span v1.539–v1.540) · analyst: Fable · 2026-08-04
TLDR: The inn room really did grow beds — one bed at t1413, two by t1428, an explicit "gap between beds" at t1431. The mechanism is a coverage gap, not a broken guard: interior detail has exactly one pin in the whole architecture — the write-once [LOCATION_DESC:] — and the GM filed one for only 4 of 50 sub-locations in this campaign, not including this room. With no pinned description, the room's furniture lived only in prose; the summarize cadence (a chapter every ~3 turns at current prose sizes) evaporated the single-bed establishment within ~2 extraction cycles, and twelve turns later the GM re-derived the room from genre priors: four sleepers, therefore multiple beds. Proposed fix: a deterministic missing-description engine nudge — the same "engine detects, GM decides" teeth shape as the quest/schedule machinery (#20/#129).

3 · Why the establishment evaporated Confirmed

Summarize cadence around the incident, from memory.chapters: extractions landed at turns 1400, 1405, 1410, 1413, 1416, 1419, 1422, 1425, 1428 — one every ~3 turns. At current prose sizes (~1,300–3,100 chars/turn against SUMMARIZE_AT=2400 estimated tokens), the live verbatim window is roughly three exchanges deep. The single-bed sentence at t1413 was extracted into a chapter by ~t1416 and left sessionLog entirely; from that point the fact existed nowhere the GM could read. Twelve turns later (t1428, the return-to-the-room scene), the GM reconstructed the room from what it had: four adults retiring for the night, an inn, genre priors. Multiple beds is the statistically sensible guess — which is exactly what drift looks like when canon has no pin: not an error against the record, but a plausible re-roll of a fact that was never recorded.

4 · Why no guard caught it Coverage gap

  1. The pin exists but is voluntary. [LOCATION_DESC:] is write-once, re-injected every turn, and would have prevented this outright. But filing it is left to the GM's initiative, and the field numbers say that initiative is rare: this save has descriptions for 12/23 world locations and 4/50 (8%) sub-locations. Interiors — where furniture-level continuity matters most — are precisely where the pin almost never gets written.
  2. Nothing detects the absence. Every other lifecycle in the engine has teeth (quest objectives #20/#129, schedules #129, arc staging #127, conditions #46, moods, relationships #61). A node with description=null generates no nudge, no warn, nothing — a silent gap by this codebase's own no-silent-failures standard.
  3. Aggravator at this room's first visit Inference: t1410 — the natural turn to describe the room — was the B21 chaos turn: the GM's budget went to the stale tide-schedule escalation, and the response was truncated mid-tag (the [SCH incident). If a trailing [LOCATION_DESC:] was coming, it died to the cut. Plausible, not provable; but it illustrates why first-visit-only filing is fragile — first visits are often the most dramatically crowded turns.

5 · Proposed solution

Primary — a missing-interior-description nudge (recommended)

buildLocationDescNudge in NOTE_BUILDERS (api.js), the established engine-detects/GM-decides shape:

  • Trigger: the party's current node (sub-location first, world node otherwise) has description=null and the party has settled — second consecutive turn at the node, or visits ≥ 2. Not on the arrival turn itself (arrival turns are crowded; that's finding #4.3).
  • Note text (sketch): "This location has no permanent description on file. In THIS response emit [LOCATION_DESC:…] — 1–2 sentences of fixed physical facts: layout, exits, and countable furnishings (beds, chairs, windows). The engine re-serves it every visit so the place stays consistent."
  • Discipline: one note per node per visit-stay (latch on the node key, re-arm on re-entry while still null); silent in combat; one per turn, sharing the existing stalest-first note budget.
  • Predicted effect: converts the 8% interior coverage to ~100% for lived-in nodes specifically — the nudge only ever fires where the party actually dwells, so it adds no prompt weight for pass-through geography.
  • ⚠ Drift surface: engine-note channel + a new consumer of the geo data — Fable-tier, test-first, per the standing policy. Estimated size: S (one builder + latch field + 3–4 engine tests).

Secondary — tags-early discipline (already under discussion tonight)

A first-visit [LOCATION_DESC:] emitted at the response tail can die to output-cap truncation (#132 made this visible; v1.540 raised the cap to 1500, shrinking but not eliminating the window). Instructing the GM to emit state tags early in the response protects every write-once tag, this one included. Same drift-gated prompt change; pairs naturally with the nudge.

Not recommended

Auto-generating descriptions engine-side (e.g., harvesting first-visit prose into node.description mechanically): tempting, but it would promote unvetted narrative sentences into permanent, every-turn-served canon — one florid or transient sentence ("smoke still hanging in the rafters") pinned forever is worse than no pin. Description content should stay a GM decision; the engine's job is making sure the decision happens.

6 · Disposition for this save

No repair needed or recommended. The two-bed room is now four turns of established, emotionally load-bearing fiction (the t1431 morning scene depends on the "gap between beds"); retconning back to one bed would cost more continuity than it restores. The right move is to pin the room as it now is — once the nudge ships, the next turn in the room files a description and the oscillation ends. (Interim manual option: an OOC GM: describe this room and file its description in-story accomplishes the same today.)
