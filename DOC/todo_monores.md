# todo_monores — Monotonic-Resources Audit (2026-07-17)

First audit run under the **standing monotonic-resources dimension** (Fable_UberAudit.md ▸ "Standing
audit dimension — monotonic resources", added the same day from the r8/jetsam postmortem). Method:
three parallel readers swept state/memory (state.js, memory.js, globals.js, helpers.js, compress.js,
tag_table.js, api.js), the game loop (game.js, char-creation.js, campaign_generator.js, stt.js,
storage-adapter.js), and the UI layer (all ten ui-*.js + index.html); the piper/SW/vendored layer was
audited directly. Every HIGH/MED claim below was **independently re-verified against the source**
before ranking — two agent findings were demoted on cross-reference (the nudge queues each have
write-side caps the drain-side reader couldn't see), one agent contradiction was resolved by reading
the code (render images ARE appended to the story DOM, but as remote URLs, not data URLs).

**Scope discovery:** the dimension's three scopes (per-call / per-turn / per-session) turned out to
extend upward — this codebase has two more: **per-campaign** (localStorage snapshots, memory blobs)
and **per-device-forever** (OPFS voice models, the purge-exempt SW piper cache). Future runs of this
dimension should enumerate all five.

**This is a hunt-only pass (user directive): nothing below is fixed.** Rows follow the house shape
(finding + remedy sketch + living status) with the new row style: **the first sentence of every row
is a plain-language TLDR.** Graduate rows into TODO.md when scheduled, per convention.

## Ranked findings

| # | Sev | Finding | Status |
|---|-----|---------|--------|
| 1 | HIGH | **The story window keeps every message of a live session in the page forever — only a reload trims it.** `addMsg` (ui-shell.js:122) appends per message with NO live trim; the only trim is `rebuildNarrativeFromTranscript(20)` (ui-boot.js:295), which runs solely at load/switch/import boundaries. Each turn adds prose + a replay button + 3 suggestion buttons; each manual render adds a toolbar + `<img>` (remote fal URL — lighter than data-URLs, per-image × Close exists, but count unbounded). The exposed profile is exactly Car Mode: a marathon session with no reload, on iOS, sharing the tab ceiling with the Piper wasm heap — the two biggest session-scope accumulators compound on the same limit. Remedy sketch: cap the live log at N message elements (evict oldest from the top; the transcript already holds the full record, and reload already proves 20 is an acceptable window). | OPEN — hunt-only pass |
| 2 | HIGH (enriches UA15) | **The full turn-by-turn prose record grows forever, and it's shipped more places than the known issue covers.** `worldState.transcript` (logTranscript, state.js:150-154; 2 entries/turn, no cap) is the KNOWN dominant blob (54% of t308; UA15 IndexedDB watch stands; LZ-compressed at the localStorage boundary since v1.227). New angles from this pass: it sits **uncompressed in memory** all session, rides **every debounced sync POST** uncompressed, rides `.tnd` exports uncompressed, and is **multiplied by row 5's per-campaign snapshots**. Remedy sketch: fold into UA15's trigger review — payload-side compression (send `serializeWorldState` output) is a server-coordinated change; note it in SERVER_ARCHITECTURE.md when UA15 fires. | OPEN — enriches the UA15 watch |
| 3 | MED-HIGH | **All the capped memory lists quietly overflow into an archive that nothing ever caps, measures, or compacts.** Every trusted cap is a funnel: lore>30 → `memory.archive.lore` (memory.js:156), decisions>30 → `.decisions` (157), chapters>10 → `.chapters` (768), core memories>25/sheet → `.coreMemories` (game.js:514), every summarize-retired fact → `.superseded` (792, grows per summarize cycle in mature play). The archive is never injected (so no prompt cost) but rides every localStorage save and sync POST forever. This is rider 1 of the audit dimension in the wild: the caps are prior fixes whose retained sink was never audited. Remedy sketch: size telemetry first (archive char-count in the mem status line or Usage modal), then a compaction story (LZ the archive at the storage boundary like the transcript, and/or an export-and-trim path). | OPEN — hunt-only pass |
| 4 | MED | **Every narrator voice you ever try is ~60–115MB on the phone forever — there is no delete button.** OPFS voice models accumulate per auditioned voice; the vendored runtime exports `remove()`/`flush()` but NO game code calls either (verified: zero call sites in tts.js), and Voice Settings has no removal UI. With persistent-storage granted (audit #12 asks for it!), auditioning four voices permanently holds ~300MB of origin quota on a device that also fights the localStorage quota. Remedy sketch: a per-voice "✕ delete" in Voice Settings' voice list wired to `mod.remove(voiceId)` (keep the active voice undeletable). | OPEN — hunt-only pass |
| 5 | MED | **Every campaign keeps a complete private copy of its whole world in localStorage until you explicitly delete the campaign.** `snapshotActiveCamp()` (state.js:308-319) writes full `tnd_camp_<id>_ws/_sl/_mem` copies (each containing that campaign's entire transcript) on switch-away/beforeunload; only `deleteCampaign` (343-346) removes them. Abandoned campaigns hold quota forever — this multiplies row 2 by campaign count on the device where quota death is the known killer (mobile). Remedy sketch: the snapshots already benefit from transcript compression (they copy the serialized form); the gap is *abandonment* — surface per-campaign storage size in the campaign picker so dead weight is visible and deletable. | OPEN — hunt-only pass |
| 6 | MED | **The NPC roster only ever grows — every named character the GM ever mints stays in the save and in every prompt.** `worldState.npcs[]` + `memory.npcs{}` grow per distinct NPC (tag_table.js:245,441; no eviction — `NPC_MERGE` only collapses confirmed duplicates, `NPC_FORGET` trims facts, death doesn't remove). Party is hard-capped (PARTY_MAX=4) but the non-party roster isn't; entries can carry charSheets; the roster line-set rides the volatile prompt half every turn and the whole array rides every sync POST. Slow per-entity growth, but it's the widest-fanout accumulator (prompt + localStorage + network). Remedy sketch: status-gated roster diet — dead/long-unseen NPCs drop out of the per-turn prompt roster (memory retains them; RAG already serves their history on relevance), not out of the save. | OPEN — hunt-only pass |
| 7 | MED | **The game re-uploads its entire world every turn and nobody is watching how big that upload has gotten.** `_syncNow` (storage-adapter.js:326-397) POSTs worldState+sessionLog+memory (debounced 1.5s, ≥1/turn) — correct for a blob-store design, but payload size is the direct sum of rows 2/3/5/6 and there is NO size telemetry, warning threshold, or ceiling anywhere. A mature-campaign phone on cell data ships multi-MB POSTs per turn silently. Remedy sketch: measure first — payload byte-count in the Usage modal (the #21 pattern), warn-toast past a threshold; compression is row 2's server-coordinated follow-up. | OPEN — hunt-only pass |
| 8 | MED | **Pop-up notices never go away on their own, and the durations callers ask for are silently ignored.** `showToast` (ui-shell.js:21-38) is tap-dismiss-only BY DESIGN ("cheers shouldn't vanish"), but multiple call sites (tts.js among them) pass a duration argument the signature doesn't have — caller intent silently dropped (a no-silent-failures violation at the API seam), and in Car Mode nobody taps, so toasts stack over the driving UI indefinitely. Remedy sketch: honor an optional duration argument when passed (callers already believe it works); keep sticky-by-default for the un-argumented "cheer" class; Car Mode already routes its own signals through carNotify. | OPEN — hunt-only pass |
| 9 | MED (latent) | **The permanent voice-engine cache will strand dead multi-MB files the first time an engine binary ships a patch.** The SW piper cache's rev-GC (sw.js:114-126, piper-audit #15) keys on *pathname + query* — it collects superseded `?tnd=` revs, but the ORT `.wasm` binaries are delivered by RENAME (documented at tts.js PIPER_ORT_PATH), and a renamed file is a NEW pathname: the old binary (~10-20MB) stays in the purge-exempt cache on every device forever. Latent — no ORT rename has shipped yet; it costs nothing until the first ORT patch, then ~20MB/device permanently per rename. Remedy sketch: on rename-delivery, add the retired filename to a small kill-list in sw.js that activate() deletes from PIPER_CACHE. | OPEN — latent until first ORT rename |
| 10 | LOW-MED | **A name-tokenizing cache grows for the whole browser session and never forgets a spelling variant.** `_npcTokMemo` (memory.js:18-29) memoizes on the RAW pre-canonicalization string — every name/alias/variant ever tokenized mints a permanent page-lifetime key (in-memory only, tiny entries; resets on reload, survives campaign switch). The closest in-code match to the r8 bug class, at 1/1000th the weight. Remedy sketch: crude size guard (if keys > ~2000, reset the memo — it's a pure cache). | OPEN — hunt-only pass |
| 11 | LOW-MED | **Merging two duplicate NPCs can push their combined fact list past its cap, and it only slowly (or never) shrinks back.** `NPC_MERGE` concatenates the duplicate's `knowledge[]` into the canonical entry (tag_table.js:224) with dedupe but no cap-12 re-check; the events list got exactly this fix (E50 re-slice at memory.js:78) but knowledge didn't get the parallel. Overfilled knowledge feeds `memoryNpcDetail` prompt injection. Remedy sketch: mirror E50 — re-slice knowledge to its cap (newest-last) after merge concat, overflow to `memory.archive.superseded`-style storage if the never-lose rule applies. | OPEN — hunt-only pass |
| 12 | LOW-MED | **A character's "story beats" list has no cap at all.** `[STORY_BEAT:]` pushes `{text,turn}` per emission (tag_table.js:465) with no cap/dedup — the only wholly uncapped list on the character schema (not prompt-injected; sheet display + sync/export weight only; emission rate is GM-paced). Remedy sketch: cap like coreMemories (evict-oldest to archive) or fold into the #40 machinery, which superseded this field's role. | OPEN — hunt-only pass |
| 13 | LOW (family) | **A dozen world-knowledge stores grow one entry per new thing the story ever names — individually slow, collectively the shape of a mature save.** The bounded-by-story-breadth family, inventoried for the record: `memory.map.nodes/locations` + per-node `items[]` (never evicted), `memory.quests{}` (every closed quest, load-bearing for the re-completion guard), inventory distinct item names, `worldState.capabilityBible` (also rides the STABLE prompt half — cache-relevant), `legacyCharsUsed[]`, the one-shot nudge latches (`reciprocityNudged`/`arcQuestNudged`/`mergeHintNudged`/`consumableNudged` — never cleared), `customRules[]` (user-paced + silent blueprint-import appends, game.js:1056; rides EVERY prompt's stable half), `tnd_camps_v1` (never-synced local entries never pruned, storage-adapter.js:407-425). No action now — this row IS the enumeration; future audits diff against it. | RECORDED — watch, no action |
| 14 | LOW | **Opening Car Mode twice without closing it would leave a permanently stuck keyboard listener.** `showCarMode` (ui-carmode.js:117-123) adds the document keydown listener without checking `_carKbHandler` is already live; a re-entrant open (button racing the boot auto-restore, ui-boot.js:352) stacks and orphans the first. Not observed live. Remedy sketch: one-line guard (remove-before-add or early-return if set). | OPEN — hunt-only pass |
| 15 | LOW | **An abandoned login popup leaves a message-listener behind.** `loginWithServer` (storage-adapter.js:119) removes its window "message" listener on auth success or detected popup-close, but not if the popup is left open forever; one listener per abandoned attempt, page-lifetime, user-paced. Remedy sketch: also remove on a timeout. | OPEN — hunt-only pass |
| 16 | LOW (accepted residual) | **The speech engine's pronunciation module keeps its peak memory for the whole session — deliberately.** The r8 recycle covers the ORT session only; the phonemizer module is retained BY DESIGN (recycling it would reintroduce the v1.323 lazy-GC leak class — documented in vits-web.js r8 comment).
