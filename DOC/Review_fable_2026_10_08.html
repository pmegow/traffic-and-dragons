8 The #599 design record — Fable's evaluation

Verdict: the direction is right and the ten rulings stand; do not build it as one series. The record (DESIGN_599_inventory_rows.md, drafted by Opus 5.5, ruled by the owner, reviewed by Astra as entry 39) gets the three things that matter right: rows with one module and one key, the GM's tag grammar untouched, and a version gate shipped first because the real risk is a stale device writing a converted save back. Its weakness is shape, not substance: it is written as a 41–64 hour big-bang that re-anchors 90 sabotage clauses, re-baselines the golden files and all four replay baselines, and flips the stored shape in the same breath as every reader — on a tree that moved 61 commits this week. Astra's review then left eleven engineering contracts open in §11 and asked for them to be "resolved before implementation", which reads as a second design round. They are Fable-sized decisions; the answers are below so the build can start.

What the record gets right

  • The gate first. worldState.ver is written as 10 in two places and read nowhere (verified). Decision 1 is the only thing that protects every later shape change, and Astra's R1 (admission must precede the four writes in _applyPulledCampaign) is the one finding that must be honoured to the letter.
  • Tolerant reader, one-way writer, writers heal on entry. The #272 transcript pattern; fixtures and shipped samples stay legal input, so the test corpus does not have to be rewritten to start.
  • The field census as a pre-switch check (11,490 entries, zero loss) and Astra's R4 correction so that erasing every equipped flag fails it. The census is evidence for legacy strings only, and the record now says so.
  • #518 kept out (decision 8): rows do not identify a transfer; that is the explicit {from, to, item, qty} record.

What to change before the first commit

  1. Sequence it as four releases, each green on master, instead of one series. (a) The gate, alone (2–3 h; ship this week). (b) inventory.js with invRows, itemKey and the §2.4 functions, the old helpers turned into one-line delegates, every reader and writer routed through the module, the boundary contract in run-tests — with the stored shape still strings. Nothing on disk changes, no baseline moves, no clause needs re-anchoring beyond the delegate lines. (c) The shape flip: invRows at the doors and the faucets, ver: 11, the census over the owner's exports, the four replays re-baselined with the "only the inventory differs" checker. This is the smallest possible commit once (b) has landed, and the only one that touches a frozen artifact. (d) [EQUIPPED:], the doc line, the strip set and the golden files — the one stable-half change, paired with #420 and #22b in one deploy as the schedule already says. The one-key convergence (§2.2: "Wolf pelt" meets "Wolf pelts" in wants and catalogs) is a behaviour change and ships as its own commit inside (b), with the compatibility table of gate 2 as its test.
  2. One sheet admission registry, not a sixth scattered step. §5.3 puts the inventory heal inside relationshipMigrateSheet. Today one adopter (adoptLibraryCompanion) already runs seven per-sheet steps by hand — identitySheetAdmit, portraitAdmit, sceneFieldsCross, relationshipMigrateSheet, adoptSheetItemDefs, voicePinsFill, stashCopyMark — plus keyedStores(sheet,"sheet"), and this week's batch added two of them. Adding an eighth is the pattern the design rules forbid. The (b) release should land SHEET_ADMISSION: one ordered table of {gate | heal} entries that every door runs through one sheetAdmit(sheet, where), with the existing seven as its first entries and the version check as its first gate. Astra's "per-sheet prompt healing is not admission" then holds by construction, and the next per-sheet rule is an entry.
  3. Resolve §11 in the record now; none of it needs the owner. Recommended contracts: qty is a safe integer in 1…9999 (QTY_MAX); a write that would exceed it refuses loudly and leaves the row; a non-finite or non-integer stored qty heals to 1 with one console line and one junk note per sheet per load (the note keyed by row, so a repeated heal cannot grow it); equipped is true only for the boolean true; a count suffix inside an object row's name is a literal name (the stored grammar applies to strings only); a same-key fold happens only when the rows' unknown fields deep-equal — otherwise both rows stay and one line says so (I2 reads "no two rows share a key unless their extra fields differ"), which is the lossless answer to I5; invRows returns the list and the caller (invHealSheet) owns sheet.inventoryJunk; a non-array container is replaced by an empty list and the original kept as junk; writers mutate the live list, and every preflight or snapshot takes a deep copy (JSON.parse(JSON.stringify(…))) — the rule Astra's R3 asks for, stated once.
  4. Keep the string-guard census out of the proof. Gate 4's planted typeof inv[i]==="string" sabotage is the right proof; the 2,077-site grep is a map. Say so in §8.2 so a green grep is never reported as coverage.
  5. Trim the record. Astra's pass made §2.2, §5.2 and §5.4 read as disclaimers ("not permission to silently choose lossy coercions"). Once item 3 lands, those paragraphs become the contracts themselves. A design record that argues with itself costs every later reader.
