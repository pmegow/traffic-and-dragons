Class Bible — character progression

Spec R1 (iteration 1 of N), 2026-07-27 · TODO #72 · scope ruled 2026-07-18 (one definitive source; CLSS migrated then DELETED) · every number below measured from the live engine via dev/load-engine.js, not from memory
What this iteration is: the ground truth of creation-time progression as it exists today, the proposed class_bible.js shape, and the design forks — each carrying a recommendation. It deliberately contains no authored content yet (no new spells, no archetype features): content authoring is iterations 2+, class by class, after the shape and the three open forks are ratified.

The foundation is better than expected. Every class-list spell already has canonical mechanics in the capability bible, so the anti-drift injection (buildSpellBibleBlock) will serve canon for anything the bible grants — new content only needs a name in the class bible plus one capability entry, and the GM sees the rules automatically. The archetype layer is the genuinely empty half: 27 archetypes with a description and nothing else.

Part II — The class_bible.js shape

C1 — Schema: one entry per class, a per-level dict, archetypes nested with their own levels. RECOMMENDED 
CLASS_BIBLE = { "Rogue": {
  id:"Rogue", hd:8, prime:"DEX", gear:"…", desc:"…",
  statPriority:["DEX","INT","CON","WIS","CHA","STR"],
  abilities:[ "Sneak Attack", "Evasion", "Lockpick" ],   // names -> capability_bible
  spellTiers:{},            // caster classes: {tierUnlockedAtLevel} + pick counts (C2)
  levels:{                  // CLASS features by level — names -> capability_bible
    2:{features:["Cunning Action"]}, 5:{features:["Uncanny Dodge"]},
    7:{features:["Evasion (Improved)"]}, 9:{features:["Blindsense"]} },
  archetypes:[ { id:"arcanetrickster", nm:"Arcane Trickster", desc:"…",
    spells:{...},           // the ARCH_SPELLS grant, folded in
    levels:{ 3:{features:["Mage Hand Legerdemain"]},     // the identity ability, NAMED
             6:{features:["…"]}, 10:{features:["…"]} }   // authored in iterations 2+
  }, … ] } }
Features become named capability_bible entries where they are actives or lookup-worthy passives (the racial_caps precedent) — which also fixes the nm:"Lv9" naming bug structurally: the sheet lists "Blindsense", and the GM gets its canon injected. Pure-flavor passives may stay prose. A coverage-guard test (again the racial_caps precedent) blocks a bible name with no capability entry from shipping.
C2 — Spell progression model. OPEN FORK
(a) auto-grant whole tiers at unlock levels — zero UI, zero choice;
(b) picks — reuse the creation spell-picker at unlock levels (SPELL_PICK_LIMITS pattern: N picks per tier), choice preserved;
(c) hybrid — auto cantrips, picks for T1+.
Recommendation: (b) picks. The picker modal already exists and is field-proven at creation; choice is the fun half of levelling; and auto-grant would dump 5-6 spells at once on a caster level. Proposed unlock rhythm (full casters): T2 picks at L5, T3 at L7, T4 at L9 — which finally makes Necromancer T4 and the AT's Oubliate reachable by progression, exactly what the tier-open-endedness note in CLAUDE.md always intended. Content cost: most classes need T4 (and a few need deeper T2/T3 benches) authored — that is iterations 2+, and every new spell is one class-bible name + one capability entry.
C3 — Fill the dead levels with an ARCHETYPE spine: L3 identity → L6 feature → L10 capstone. RECOMMENDED
Class features already own L2/5/7/9; stat bumps own L4/8. Giving archetypes L3/6/10 interleaves the two tracks so every level grants something, and L10 stops being an empty finale:

Authoring cost, stated honestly: 27 archetypes × (named identity + L6 feature + L10 capstone) = ~81 authored features, plus the spell-bench expansion. This is the iterative bulk, and it is per-class shippable — one class can go fully live while eight still run the legacy grid.
C4 — The L10 / 64k XP ceiling. OPEN FORK
(a) soft-cap: L10 stays max; past 64k, every further ~20k XP banks an epic boon (small GM-offered list — the prestige shape);
(b) extend the table to L12 or beyond — more levels, more authoring, bigger balance surface;
(c) deliberate end — campaigns conclude at L10, XP past it is score.
Recommendation: (a) soft-cap with boons. It keeps the authored balance surface bounded at 10 levels, mature campaigns (the product's proven strength) keep earning something, and boons can reference the capability bible like everything else. (c) fights the evidence — the live campaign is at t1188 and nowhere near done; (b) is the biggest authoring bill for the least distinct payoff.
C5 — Skills stay usage-driven; classes touch them only at creation, if at all. OPEN FORK — scope question
The 37-skill system levels by doing (success counts vs SKILL_THRESHOLDS) — orthogonal to XP and working in the field. Options: leave untouched (recommended for v1); or classes seed starting Familiar ranks in 2-3 signature skills (a Rogue starts Familiar in Stealth/Lockpicking — one-time creation seed, zero ongoing coupling). Anything deeper (per-level skill grants) would collide with the usage philosophy and is not recommended in any iteration.
C6 — Landing sequence (already ruled + the invariant). RATIFIED 2026-07-18
① classDef(id) becomes THE lookup, collapsing ~30 hand-rolled loops — pure refactor, shippable alone. ② The backing store swaps to CLASS_BIBLE inside that one helper. ③ CLSS deleted. Invariant test at every step: an existing character's derived values must not move — load the live save before/after and assert identical hit die, features, archetype list, stat priority. Mid-campaign characters must not retroactively gain or lose anything; new grants apply only at their NEXT level-up. ⛨ Drift surface at step ② onward (level-up write path + char sheet + the bible-injection blocks): Fable builds those steps.
