Speaker Casting — the 904-voice stable

Spec R1, 2026-07-24 · TODO #95 · the un-shelving of #9⑦, enabled by server TTS (#90) · measured foundation: 3 distinct speakers through ONE warm daemon at RTF 0.15–0.16, live box

Why now. When #9⑦ was shelved, per-speaker voices meant patching the vendored wasm runtime (the r-rev delivery trap) and auditioning meant downloading models. Server TTS dissolves both: the piper daemon already accepts speaker_id per JSON request line (proven — no new daemon, no cost change), and audition audio can be synthesized on demand with the user's OWN text — which also delivers the #9⑧ custom-sample wish. The default model every device already has (en_US-libritts_r-medium, LibriTTS-R = restored/cleaned source audio) carries all 904 speakers in its existing 75MB. Kokoro's K3 design survives here: a speaker id is exactly what a kk_ id was — server-renderable, locally only approximable — so the tier-aware resolution thinking transfers.

Decisions S1–S5 (all with recommendations; S2 is the only real fork)

S1Id format: <modelId>#<speaker>, e.g. en_US-libritts_r-medium#204. Split on the LAST #; base id must be in the curated catalog; speaker must be an integer in the model's speaker_id_map values (0…num_speakers-1). Rides everywhere a voiceId rides today (charSheet.voiceId, worldState.piperVoice, speaker maps, blueprints) — strings, no schema change.
S2Offline behavior: NO vendored-runtime patch. Local Piper (vits-web) can't select speakers unpatched; a patch means a PIPER_RUNTIME_REV bump into the permanent-cache delivery trap plus wasm surface the whole B9 arc argues against touching. Instead: local reads STRIP #speaker and speak the base model (its default speaker) — same voice family, loud console line once per session. Server reads get the real speaker. Revisit only if offline speaker fidelity ever becomes a real want.
S3Audition surface = speaker_browser.html, a NEW satellite (single-purpose rule; voice_picker.html stays the model picker). Reads the session token from localStorage (same-origin, the blueprint-designer precedent), synthesizes the user's own text via POST /api/tts with speaker ids, plays inline. Requires connection; says so plainly when absent. Must be added to sw.js's network-first allowlist (the bug_tracker lesson) — or, like blueprint-designer, kept OUT of the app shell entirely (recommended).
S4Gender metadata: the config's speaker_id_map keys ARE LibriTTS reader ids, and LibriTTS publishes per-reader gender. Generate libritts_speakers.json ({readerId:{g,spk}} → 904 entries, a few KB) once at build time; loaded ONLY by the satellite (the in-game dropdown shows starred voices, so the table never ships in the app shell). If the metadata can't be fetched reliably, ship without the gender filter and file a follow-up — do not guess genders.
S5Starred set: device store (tnd_speaker_stars_v1, [{id,label}] with user-editable labels like "Gravelly innkeeper"). Feeds a "★ Cast voices" optgroup in the existing sheet Voice dropdown and the Voice Settings narrator dropdown. Device-level on purpose — stars are picker convenience; the actual binding (charSheet.voiceId) already rides sheets and sync.

Required correctness piece — base-model awareness in the protection layer

_voiceAssignedTo, the LRU stamps, eviction, and releaseVoiceIfUnused all compare voice ids EXACTLY. Under S1, five characters can use …#204/#611/#88… while the LRU knows only the base id — so releasing a reassigned voice could delete the ONE model they all depend on. Every protection/eviction/download decision must normalize through a voiceBaseId() helper first (one helper, used everywhere — no scattered splits). This is the #95 equivalent of the F11 class and gets a VOICE DELETE CONTRACT clause.
