W2 — referential integrity for high-impact writes

Recommend Approve a two-phase build: resolved scene handles gate death/merge first; quest completion and rewards follow only after the transaction envelope is in place.

Proposed state shape

worldState.sceneRefs = {
  scene: "loc-key|sub-key|scene-serial",
  actors: [
    { h:"r1", name:"Mokmurian", kind:"npc", present:true,
      sourceTurn:1645, evidence:"tag|narration|combat" }
  ],                         // cap 10; loud refusal on the 11th
  negatives: [
    { h:"r2", not:"Mokmurian", sourceTurn:1638, source:"gm-committed" }
  ]                          // cap 6; structured, never reconstructed by prose regex later
}
  • The ledger is replaced on a scene transition; it is not an append-only history.
  • Entries are created only for identity-bearing scene evidence, not every name on every turn.
  • A handle identifies the actor in this scene. The canonical NPC key remains the durable identity. The two are never silently substituted.
  • Player statements and conditionals may create intent/assertion evidence, never observed-world evidence. “If the giants are moving” cannot become an army fact.
  • Explicit negative identity is extracted as a typed constraint while the source window is live. No later regex tries to rediscover “not Mokmurian” from compressed prose.

The preflight produces a mutation plan against clones. Only a fully valid plan applies. A death cannot stamp while its quest/reward half is rejected, and a retry cannot pay twice.

Mokmurian regression fixture

The t1638 “not Mokmurian” actor receives one handle. The t1645 target name resolves to a different canonical key while the physical action still targets that handle. The conflict quarantines Mokmurian died, allows the anonymous/deceptive scholar’s death, leaves the strike objective open, and pays no identity-dependent reward. This is the acceptance test, not an invented benign scene.

Owner decision W2. Approve the phased shape above? Recommended answer: W2 approve — death/merge gate first; transaction envelope before quest/reward.

W6 — atomic summary validation

Recommend Ship canonical identity validation first. Defer recurring-proper-noun registration proposals to a second phase so a safety validator is not coupled to a new entity faucet.

Staging contract

  1. The extractor receives a compact canonical identity table for the player, party, and principals: exact key, aliases, gender/pronouns, dead/alive, and scene handle when present.
  2. The JSON result is parsed into a staging object. No memory, NPC, quest, chapter, or archive write occurs yet.
  3. A deterministic validator checks every named/pronominal assertion against that table and W2’s scene constraints.
  4. A high-confidence contradiction rejects the entire extraction by throwing into the existing bounded summarize failure path. There is no blind pronoun replacement and no partial chapter commit.
  5. After the existing retry ceiling, the degraded raw chapter is filed with a validation receipt and without the rejected structured claims. It cannot re-inject the contradicted sentence as canonical summary text.

Pronoun test

A chapter sentence whose sole named antecedent is male Ammut and whose subject is “she/her” is rejected. A sentence about a separately named female actor passes. Ambiguous plural/quoted speech is not “corrected”; it is either allowed as ambiguous or rejected for retry. The validator never rewrites prose to manufacture confidence.

Recurring proper nouns

If approved later, the extractor may propose—not file—an unregistered proper noun after repeated chapter presence. Queue cap 3, once-per-name latch, supporting turn list capped at 4. Confirmation uses a dedicated proposal channel; it does not overload merge hints or automatically create an NPC. This is the Sable remedy without recreating the identity-fusion faucet.

Owner decision W6. Recommended answer: W6 approve validator; defer recurring-name proposals.

W7 — separate durable bond from current dynamic

Recommend Adopt the two-axis model. Migrate every legacy descriptor conservatively into bond, leave dynamic empty, and require explicit axis operations from then on.

Schema and boundedness

{ entity:"Frizwick",
  bond:"Wife — beloved family", bondTurn:1668,
  dynamic:"Favor collected, warming", dynamicTurn:1666 }

Exactly one bond and one dynamic per resolved pair. Updates overwrite their own axis and stamp a turn; there is no per-change array. Existing core memories remain the historical record.

Migration

  • Every legacy descriptor moves verbatim to bond. This may conservatively treat “wary ally” as durable, but it destroys nothing and never demotes a wife to a passing favor.
  • No lexical classifier decides the migration. W1’s regex remains a warning/audit aid, not schema authority.
  • Player and companion reciprocal rows migrate independently, then the reciprocity audit surfaces disagreements. Migration never invents a mirror.

Write authority

OperationMeaning
[RELATIONSHIP_BOND:entity|text]Creates/replaces durable kinship, marriage, sworn allegiance, enmity, or another standing bond.
[RELATIONSHIP_DYNAMIC:entity|text]Creates/replaces the current situational dynamic without touching the bond.
Companion-prefixed twinsSame axes on the named companion sheet.

Legacy [RELATIONSHIP:]During one compatibility window, refuse loudly when a pair already exists and ask for an axis. For a new pair, queue an axis-choice note rather than guessing.

Prompt/UI render Bond and Current dynamic as labeled fields. RAG, core-memory triggers, reciprocity, downgrade checks, export/import, character swapping, and removal paths all consume the same two-field adapter—no scattered “if old/new” branches.

Owner decision W7. Recommended answer: W7 approve — all legacy descriptors migrate to bond; explicit bond/dynamic tags.
