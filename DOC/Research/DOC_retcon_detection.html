1. The problem

When the GM retracts its own PRIOR turn's content inside a new response without emitting [RETCON:], the false prior turn stays RAG-indexed forever. Retrieval later serves the retracted scene as episodic truth — the exact pollution class the tag was built to kill, entered through the one door the tag can't see: the GM narrating a correction without declaring it.

3. Why Sol rejected the delayed nudge — and what the rejection actually pinpoints

The obvious fix was a detector that notices an un-tagged retraction at turn N and nudges the GM to emit [RETCON:] on turn N+1 or N+2. Sol rejected it: the tag's de-index semantics eat the correcting entry and its predecessor, so a LATE tag would de-index turns N+1/N+2 while the false turn N stays indexed — the medicine lands on the wrong patient.

The key observation: that objection is an artifact of ADJACENCY-ADDRESSED marking, not of delayed delivery. If the tag could name its target turn, a late tag would be exactly as safe as an immediate one. Fix the addressing and the rejected shortcut becomes the correct design.

4. Proposed design — three independent pieces

4a. Turn-addressed [RETCON:what|turn] (vocabulary extension, drift surface)

An optional second field names the retracted turn. [RETCON:the vault was never opened|1612] rc-marks every GM entry of turn 1612 (plus the correcting entry, as today). The bare one-field form keeps its exact current adjacency behavior — zero migration, the extension is additive. Parse lives in logTranscript beside the current rc-mark; the arbitrary-turn mark routes through mutateTranscriptEntry (#177 made this safe). Tag-table docs/strip ride the same commit (the phantom-tag class is impossible by construction in the UA1 table).

4b. The retraction detector (corpus-gated, GM-decides, never auto-marks)

A commitGmTurn observer in the shipped mold (#158 phase mismatch / #172 person drift): scan committed CLEAN prose for high-confidence retraction shapes anchored to the prior turn's content. Candidate cues, deliberately narrow: correction: / in truth, <X> never… / that was not <on-file NPC> after all — plus a REQUIRED overlap condition: the sentence must name an entity that appears in the previous GM entry's e.n index (retractions are about something; free-floating "actually" is speech). On fire: arm a one-shot nudge — "if the previous narration was retracted, emit [RETCON:what|<N>]; if it was only a clarification, do nothing" — with the turn number pre-filled. The GM stays the only writer; prose never auto-marks.

Enable gate: the detector ships DISABLED until a full-transcript precision audit (the t1788 corpus, 3,573 entries — the #158 standard: the audit's alert count must be dominated by true positives, and the phase detector's bar was ONE alert in 328 turns). If the cue set can't reach that precision, the detector half is abandoned and only 4a + 4c ship — a turn-addressed tag the GM can use spontaneously is already strictly better than today.

4c. The owner-side repair operation

A receipted dev/console operation — rc-mark turns N..M, reason, preimages to memory.archive — for historical cleanups (the t1788 bundle wanted exactly this shape). Post-#177 it is a ten-line function over mutateTranscriptEntry; it belongs beside the bundle script's other receipted ops.

6. Test plan (when implementation is approved)

  • Failing-first: [RETCON:x|N] marks turn N's GM entries and NOT N+1's; bare form byte-identical behavior to today (corpus replays byte-identical).
  • Detector fixtures from the audit's true/false positives; the negative set (clarifications, speech, "actually" as filler) must stay silent.
  • Memo safety: rc-mark of an old entry through the seam invalidates (the #177 tests already pin the accessor).
  • Sabotage: detector-disable, overlap-condition-removal, and turn-parse mutations must each go red with mustFail attribution.
