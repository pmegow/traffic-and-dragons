⚔ App Store vs Browser

An honest assessment of Traffic and Dragons as a native iOS/Android app versus what it is today
Written 2026-07-12 · grounded in: ~10K lines of dependency-free JS · BYOK (players bring their own Anthropic key) · free static hosting on Cloudflare Pages · optional Fly.dev sync server · multiple shipped versions per day

1 · Security

ROUGHLY A WASH, LEANING WORSE AS AN APP

Today (browser)

  • API key sits in plaintext in localStorage and calls Anthropic directly via the anthropic-dangerous-direct-browser-access header — the header name is honest.
  • In practice the exposure is small: no third-party scripts, no shared user content, no server holding anything valuable.
  • The key is the user's own key — a leak costs the user their own money, not yours.
  • Threat model is basically "someone with physical access to your device."

As a native app

  • Keychain / Keystore for key storage — genuinely better per-device.
  • But you almost certainly can't ship BYOK to consumers through the App Store. Apple reviewers regularly reject "paste your own API key to make the app work" apps as incomplete / against IAP rules.
  • A store app effectively forces a proxy server holding your Anthropic key — with accounts, metering, and abuse prevention.
  • That flips the security posture: today there is almost nothing worth attacking; as a store app there is a server whose compromise burns your money at API rates.
VerdictNative is more secure per-device; the business model it forces is a much larger attack surface. Net: roughly a wash, leaning worse.

2 · Profitability

BROWSER WINS — DECISIVELY

Blunt version: today this earns $0 and costs ~$0. As a store app it would earn approximately $0 and cost real money.

FactorReality
Token cost per turn Measured audits show ~$0.32 / 8 turns (≈4¢/turn with prompt caching). An engaged player running a 300-turn campaign costs $10–15+ in tokens — on your dime under a store model.
Store economics Subscription must be priced above your heaviest user's burn, minus Apple's 15–30% cut, plus the $99/yr developer fee, plus server costs. This is the AI Dungeon unit-economics problem, at hobby scale, without their audience.
Market size Real but tiny: solo AI-narrated text-RPG enthusiasts. App Store discoverability for a niche text game with no marketing budget is effectively zero organic installs.
Current model Free game, players pay Anthropic directly — the only configuration where this project is financially self-sustaining.
VerdictConverting to an app doesn't create a business; it creates a billing obligation.

3 · Maintenance

BROWSER WINS — THE STARKEST DIFFERENCE

Today (browser)

  • Edit file → bump APP_VERSION → push → live on Cloudflare in seconds.
  • v1.27x and climbing, with nightly batch playtest runs.
  • That cadence is the development methodology — the whole anti-drift stack was built through rapid ship-test-audit loops.

As a native app

  • Every release goes through review — hours to days on iOS, less on Android but never zero — on two platforms.
  • Xcode/SDK churn and annual OS-compatibility work.
  • The server (billing + proxy) becomes mandatory, load-bearing infrastructure instead of optional sync.
  • The nightly-iteration workflow dies on day one.
VerdictFor a solo maintainer, this is the difference between a project that stays alive and one that stalls.

4 · CarPlay — the uncomfortable truth

DEAD END — NATIVE DOESN'T GET YOU THERE

Going native does not get you CarPlay. CarPlay apps require entitlements Apple grants per-app, only in approved categories: audio, messaging, navigation, EV charging, and a few others. Interactive games are not an approvable CarPlay category, period. A voice-driven RPG would have to masquerade as an "audio app," and the entitlement review would catch it.

Android Auto is barely better — its games category is parked-only, on select head units.

Meanwhile, the existing Car Mode (phone browser + TTS + voice input, audio over Bluetooth to the car) already delivers the actual experience — hands-free narrated play in the car — without needing anyone's permission. It's not on the head-unit screen, but for a game you shouldn't be looking at while driving, that's arguably correct.

If CarPlay was a motivation for the app conversion, it's a dead end.

5 · What a full conversion would take

Path A — Capacitor wrapper (the only sane one)

The zero-dependency ES5 codebase is unusually easy to wrap:

  1. Wrap + build pipeline — Capacitor shell, iOS + Android projects, icons/splash. ~1 week. The no-build-step architecture survives intact.
  2. Storage migration — localStorage → Capacitor Preferences/SQLite. Ironically this deletes problems: the quota ceiling that forced transcript compression (v1.227) vanishes. ~1 week including migration of existing saves.
  3. Key storage — Keychain/Keystore plugin. Days.
  4. Native TTS/STT — replace Web Speech with Capacitor plugins (better voices, background audio for Car Mode). ~1 week.
  5. The real project: the proxy/subscription server — store distribution to strangers rules out BYOK, so: accounts, Anthropic proxy with your key, per-user metering and hard caps, IAP receipt validation (StoreKit 2 + Google Play Billing), abuse handling. 1–2 months — and it's the part that never stops needing maintenance.
  6. Store overhead — privacy policy, review compliance (AI-generated-content policies apply; the 18+ adult-content toggle needs age-gating or removal for review), screenshots, review cycles. ~2 weeks and recurring friction.
ScopeEstimateNotes
Hobby wrapper 2–4 weeks part-time Keep BYOK, distribute via TestFlight / sideloaded APK to yourself and friends. Viable — no review fight, no server.
Commercial store product 3–6 months Plus permanent server/billing costs and the 15–30% platform cut.

Path B — full native rewrite (Swift/Kotlin or Flutter)

4–6+ months to reimplement 10K lines of battle-tested state/memory/tag machinery — by the project's own drift-protection decree the riskiest possible move — for zero user-facing gain over Path A. Don't.

Bottom line

The browser version isn't the compromise — it's the correct architecture for what this is. BYOK is the only viable economics, instant deploy is the only viable dev cadence for a solo project iterating this fast, and CarPlay is unobtainable regardless of platform.

The one conversion that makes sense is the cheap one: a Capacitor wrapper distributed outside the store (TestFlight/sideload) purely for native storage, better TTS, and a home-screen app feel — keeping BYOK and the current server exactly as they are.

The full commercial store conversion only makes sense if the goal changes from "build my ideal RPG" to "run a small AI subscription business" — and those are very different projects.
