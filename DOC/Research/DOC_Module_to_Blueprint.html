Module → Blueprint

Conversion instructions + the Tomb of Annihilation case study · v2, 2026-07-05 · Reference template: tomb_of_annihilation.blueprint (the most complete example — creatures, act & arc rewards, dnaHints). Part I is the story and the why; Part II is everything needed to convert a module cold.

0 · The one-sentence version

A blueprint is not a summary of a module. It is the minimum set of anchors that keeps the GM canonical while it improvises everything else — a spine of acts, a cast with secrets, a handful of fixed places, a bestiary, and rules that guard the module's soul. Everything that doesn't anchor something gets cut.

PART I — How the ToA conversion actually happened

1 · Learn the format from the engine, not from memory

First move was not writing content. It was discovering what a blueprint actually is to the code that consumes it:

  • Read the reference template: today that is tomb_of_annihilation.blueprint — it exercises the full current schema. (At authoring time the reference was the older, simpler rise_of_the_runelords.blueprint, which is still useful as a minimal example.) A good reference answers every shape question by example: how NPC notes are voiced, how long a location description runs, what an arc objective sounds like.
  • Read the choke points: normalizeBlueprint() and validateBlueprint() in game.js are the enforcement layer. applyBlueprint() answers the more important question: what does each section become in-game?
  • Query the vocabularies live: tone ids and prose-voice ids come from TONES and AUTHORS in data.js (Part II lists them, but the code is the truth if they've grown).
Why this matters: every section has a runtime destiny, and knowing it changes how you write. NPC notes become the GM's private knowledge base — so write secrets, not marketing copy. Location descriptions become permanent canonical text injected every visit — so write to constrain drift, not just to evoke. Creatures and rules ride the cached stable half of every single prompt — always in front of the GM, and each line costs attention on every turn.

2 · Find the module's load-bearing skeleton

Tomb of Annihilation is ~256 pages: a city gazetteer, a country-sized hexcrawl, two dungeon complexes, a hundred named NPCs. The compression question: what is the story of this module when you can only keep the spine? ToA's spine is a three-act structure wearing a sandbox costume:

Module chunkBecameReasoning
Ch. 1 — Port NyanzaruAct 1 · Port of Last HopeThe setup act: four arcs = the four things every table actually does there (meet the patron, navigate the princes, pick a guide, first expedition).
Ch. 2 — the hexcrawlONE arc + one ruleThe engine has no hex grid; the jungle's job is texture and attrition, which the "Chult itself is an antagonist" rule delivers every turn. Destinations that matter survived as locations and arcs.
Ch. 3 Omu + Ch. 4 FaneAct 2 · parallel: trueGenuinely open-order content maps to the engine's parallel flag: shrines, Fane, Red Wizards in any sequence — the GM weaves hooks, the player picks.
Ch. 5 — the TombAct 3, serial, three arcsLinear descent split at its natural joints: trap gauntlet, the Sewn Sisters (the dungeon's one social beat), the Soulmonger finale.

Turning points are act-transition triggers ([ACT_COMPLETE:]) — each written as a concrete, recognisable event, not a vibe. Rewards (act and arc) are granted in the same GM response as the completion emission, so finishing always pays out — including props a later arc needs (ToA's puzzle cubes are literally this pattern).

The cut rule: an arc must be an objective a player can complete, not a place that exists. Fort Beluarian, Nangalore, Hrakhamar, dozens of hexes — cut. Places with no objective became location seeds (if plot-critical), flavour inside other entries (Firefinger rode along in Azaka's notes), or nothing. The GM re-invents connective tissue better than a blueprint can prescribe it.

3 · Casting: who earns an NPC slot

An NPC earned a seed by hitting two of three: plot-load-bearing, recurring, carrying a secret that changes play. That produced 11 from a hundred names. Secrets go IN the notes (the blueprint is a GM-side document — Azaka's entry says weretiger on turn 1 so the GM can foreshadow it). Notes are run instructions, not encyclopedia entries: "can be bargained with — but never trusted" beats a paragraph of history. Choices the module offers stay choices (both guide candidates seeded). Roles stay coarse — Artus Cimber is neutral because pinning the module's best wildcard would flatten him.

4 · Locations: anchors against drift

Only must-pass-through places, written as canonical descriptions the engine injects permanently. Each carries one fact the GM must not lose (Omu's nine shrines; the Tomb's "cradle no light should ever have touched"). Register: postcard plus load-bearing facts — over-specify and you choke the GM, under-specify and Port Nyanzaru becomes a generic fantasy port.

5 · Rules: guard the module's soul, one failure mode each

Rules are the most expensive real estate — injected every prompt. Each of ToA's six prevents a specific, predictable failure:

RuleFailure it guards against
"Adapted from ToA — stay true, adapt freely"Canon drift in both directions.
Death curse as a HUMAN clockNo doom-counter mechanic exists; urgency must arrive through Syndra visibly dying and funerals in port.
Jungle as antagonistThe deleted hexcrawl's job, reassigned.
Chultans vibrant, never primitiveThe genre's colonial cliché — a live risk with a pulp voice at the wheel.
Nine trickster gods, NAMED, with naturesShrines degenerating into generic puzzle rooms.
The tomb kills fairly — telegraph everythingArbitrary deaths; Acererak only works if you lose to your own choices.
The name-drop lesson (2026-07-05 review): the trickster-gods rule originally referenced "I'jin's caprice, Obo'laka's caution…" without naming all nine anywhere. A rule that points at data the document doesn't contain makes the GM improvise exactly the canon the blueprint exists to pin. Fixed by putting the full roster into the rule. A blueprint must contain what it references. (Known open instance: six of the seven merchant princes are unnamed.)

6 · Validate through the real engine — all the way into the prompt

The file is done when the GM's actual prompt contains what the module needs, not when the JSON looks right. The ToA verification ran the real game code headlessly (exact command in Part II §13): parse → normalize is a no-op → validate clean → shape-diff against the reference → applyBlueprint() → buildSysPrompt() and read the BESTIARY block with your own eyes.

7 · The schema and the conversion evolve together

The first ToA pass had no home for creatures or rewards — both surfaced as designer feedback within a day and became schema features (v1.176/v1.178). Moral: when a module has something important with no schema home, that's a schema feature request, not something to cram into a rule.

PART II — The cold-start reference

Everything below is sufficient to convert a module without repo spelunking. When this document and the code disagree, the code wins — re-derive per Part I §1.

8 · The schema (tnd-blueprint-v1, as of v1.179)

{
  "format": "tnd-blueprint-v1",            // required, exactly this
  "name": "Tomb of Annihilation",          // required — also the library slug source
  "author": "credit line",                  // optional
  "tone": "swords",                         // one of: high | gritty | swords | horror | politic | custom
  "proseAuthor": "howard",                  // AUTHORS id or "" (player can override in Dev Mode)
                                            // ids: gaiman abercrombie dinniman clines leguin howard
                                            //      cook wells muir abnett rice poe lovecraft
  "startingLocation": "Port Nyanzaru",      // overrides the wizard's pick
  "startingRegion": "Chult",
  "premise": "One paragraph…",              // required (or acts) — becomes skeleton.premise, in every prompt

  "acts": [{                                // ≥1 act; act 1 activates on start
    "title": "…", "goal": "…",              // both required per act
    "turningPoint": "…",                    // concrete event — the [ACT_COMPLETE:] trigger
    "reward": "…",                          // optional; granted WITH [ACT_COMPLETE:], milestone scale
    "parallel": false,                      // true = all arcs active at once, player picks
    "arcs": [{                              // ≥1 arc per act
      "title": "…", "objective": "…",       // both required — objective = completable, never a place
      "type": "social",                     // "" | combat | investigation | exploration | social
      "reward": "…",                        // optional; granted WITH [ARC_COMPLETE:]
      "dnaHint": "…"                        // optional; HOW to run the arc (overrides generic type hint)
    }]
  }],

  "npcs": [{                                // seeded into the roster + GM knowledge base
    "name": "…",                            // required
    "role": "ally|enemy|neutral",           // free text, these three are conventional
    "pronouns": "she/her",
    "notes": "run instructions + SECRETS"   // becomes memory.npcs[name].knowledge — GM-only
  }],

  "creatures": [{                           // the bestiary → STABLE prompt half, every turn
    "name": "…",                            // required
    "kind": "beast|undead|aberration|…",
    "threat": "low|moderate|deadly|apex or a CR",
    "notes": "nature, behaviour, tactics, how it dies"
  }],

  "locations": [{
    "name": "…",                            // required
    "description": "…"                      // canonical, injected permanently on every visit
  }],

  "rules": [ "one hard GM directive per entry" ]   // → customRules → every prompt
}

Runtime destinies (what each section becomes): premise+acts → worldState.skeleton (paced by buildSkeletonBlock); npcs → roster + memory.npcs[].knowledge; creatures → worldState.bestiary → BESTIARY block, stable half; locations → map nodes with permanent descriptions; rules → customRules, every prompt.

9 · Size budgets

Targets, not laws — ToA's actual numbers in parentheses. Overshooting costs prompt attention on every turn of the campaign.

SectionBudgetNotes
Acts3 (3)More than 4 usually means you're transcribing chapters, not finding the spine.
Arcs per act2–4 (4/4/3)Each must be independently completable.
NPCs8–12 (11)Two-of-three test: load-bearing / recurring / secret-that-changes-play.
Creatures4–8 (6)Signature monsters only — the ones that carry the module's identity.
Locations6–10 (8)Must-pass-through places only.
Rules4–6 (6)One per predictable failure mode. No lore-dumps as rules.
Premise1 paragraph (~120 words)World, threat, why it matters, why the player is involved.

10 · Exemplars — the register each section wants

NPC notes: run instructions with the secret included

✓ Like this (Azaka, ToA)"Chultan jungle guide — capable, proud, and cheap, because she has her own reason to go inland: a stolen family mask she means to recover from Firefinger. Secretly a weretiger; her secret surfaces under the full moon or in desperate battle."
✗ Not this"Azaka Stormfang is a female Chultan human who works as a guide in Port Nyanzaru. Guides in Chult typically charge varying rates. She has a connection to Firefinger and an interesting secret that may be revealed later."

The good one tells the GM how to run her (motive, price, when the secret fires). The bad one hides the secret from the one reader who needs it, and says nothing playable.

Location descriptions: postcard + load-bearing facts

✓ Like this (Omu, ToA)"The forgotten city… now a drowned ruin in a sunken valley, ruled by a tyrannosaurus the kobolds call the King of Feathers. Nine shrines to nine dead trickster gods hide nine puzzle cubes, and beneath the royal palace coils a temple of serpents."
✗ Not this"Omu is an ancient ruined city deep in the jungle. It is mysterious and dangerous, full of crumbling buildings and hidden threats. Many have entered; few have returned."

The good one anchors the facts the campaign breaks without (nine shrines, nine cubes, the Fane below). The bad one could be any ruin in any module — it constrains nothing, so the GM will drift.

Arc objectives: completable, never geographic

✓ Like this"Infiltrate the yuan-ti temple beneath Omu, deal with or destroy the fallen paladin Ras Nsi, and take the final puzzle cube from his coils."
✗ Not this"The Fane of the Night Serpent" — a place is not an objective; the engine can never emit [ARC_COMPLETE:] against it.

Rules: directive + the data it needs, self-contained

✓ Like this"The death curse is the campaign's clock — make it felt through people, not mechanics: Syndra visibly worse at each meeting, funerals in Port Nyanzaru… If the player character was ever raised from the dead, the curse touches them personally."
✗ Not this"Remember the death curse is important." — no behaviour specified; or a rule that references named entities ("the nine gods") without naming them — a blueprint must contain what it references.

Creatures: nature, behaviour, how it dies

✓ Like this (King of Feathers)"The tyrannosaurus that rules the ruins of Omu. The kobolds worship it; the yuan-ti avoid it. Swallows prey whole, hunts by movement, and cannot be fought fairly — only fled, tricked, or fed."
✗ Not this"A big dinosaur that lives in Omu. Very dangerous. High HP and attack." — stats are the engine's job ([COMBAT_START:]/[COMBAT_STATS:]); the blueprint's job is character.

11 · Tone & voice selection

Tone gates content-DNA: high (heroic fantasy) · gritty (low magic, consequences) · swords (pulp sword & sorcery — ToA's pick: physical danger, wonder, hostile wilderness) · horror (dread-forward) · politic (intrigue) · custom. Voice pins prose style; pick the author whose table-feel matches the module (ToA → howard; Runelords → abercrombie). The player can override the voice in Dev Mode — pinning it is a recommendation, not a lock.

12 · The conversion checklist

  • Read the reference template tomb_of_annihilation.blueprint + Part I §1's choke points if anything looks off — the code is the spec.
  • Write the premise: one paragraph — world, threat, stakes, why the player.
  • Find the act structure (usually 3). Turning points = concrete recognisable events.
  • Arcs = completable objectives, never places. Flag open-order acts parallel. Type each arc. Add dnaHint where the module has a distinctive way the content should FEEL.
  • Rewards on arcs and acts — especially props later content depends on; act rewards at milestone scale.
  • Cut ruthlessly (budgets §9): anything anchoring nothing becomes GM improvisation, which is a feature.
  • Cast by the two-of-three test; secrets IN the notes; notes as run-instructions; preserve the module's real choices as choices.
  • Creatures: the signature monsters — nature, behaviour, how it dies. No stats.
  • Locations: must-pass-through only; each description carries its load-bearing facts.
  • Rules: one per predictable failure mode, self-contained, each earning its per-turn cost.
  • Name-drop audit: everything any rule, note, or description references by name must be defined somewhere in the document.
  • Pick tone + voice from the real vocabularies (§11).
  • Validate (§13) — through the engine, into the prompt.
