The Serialization Diet

The problem in one paragraph

Every gameplay turn re-serializes the whole campaign roughly six times (four saveAll bursts + two POST payload stringifies), LZ-compresses the full ever-growing transcript up to three times, and uploads the full state twice. A canon-envelope turn additionally JSON-round-trips the ENTIRE worldState — transcript and base64 portraits included — per envelope. The #92 wire form, a genuine localStorage win, inflates network bytes ~1.33× versus plain JSON (compressToUTF16 output is ~3 bytes/char as UTF-8), and its size telemetry under-counts real bytes ~3×. NPC-merge pre-images embed base64 portraits into the uncompressed memory blob forever. All of it is O(campaign) per turn, doubling every ~2000 turns. Constraint above all: the transcript is SACRED — never trimmed, capped, or restructured in content (owner decree 2026-07-17). Everything below changes how bytes are encoded and moved, never what the record says.

2 · Constraints the design must not break

  • Sacred transcript — content untouched, always the plain array in memory; only the storage/wire encoding may change. .tnd exports keep the plain array.
  • UA6 ordering — mutated state + history persist BEFORE any display step; a display throw must leave a consistent save that replays from the transcript.
  • Tolerant inflation, forever — parseWorldState/inflateWorldStateSnapshot accept every form ever shipped (plain array, {__lz}, plus anything added here). Inflaters ship at least one release BEFORE their producer emits on the wire (the cross-device skew rule — an old client must never pull a blob it cannot read; the UA3 rescue is the backstop, not the plan).
  • JP0-11 — the page-hide flush is synchronous and byte-capped (56KB); any wire encoding must have a sync path.
  • Cross-device preference — mobile and desktop stay in sync as much as possible; deferrals must be flush-covered.
  • No deps, ES5 — everything hand-rolled or already vendored; CompressionStream is the one platform API considered (and only as an optional later layer).
  • Drift decree — serializeWorldState/transcript integrity is core drift surface: failing-test-first, byte-round-trip tests mandatory, sabotage-proven.

3 · D1 — one save, one LZ pass, one POST per turn (f70 lever a)

Reorder commitGmTurn so every transcript mutation of the turn lands before ONE save.

  1. applyMuts(resp, {deferSave:true}) — a new option on applyMuts itself (the f70 verifier's correction: the existing deferCommit at the applyMutsTable layer is already in use and cannot be reused) that skips the trailing saveAll. Passed ONLY by commitGmTurn; every other caller (syncCharSheet, review calls, imports) keeps today's immediate save.
  2. Split narrateWithSpeakers into a synchronous derive+stamp half (speaker map, .sp stamp, auto-cast voice pinning — all worldState writes) and a speak half. commitGmTurn calls derive+stamp BEFORE its save; the standalone saveAll inside narrateWithSpeakers goes away (single-caller function).
  3. The ONE saveAll() then runs at the current commit-save site — still before addMsg/TTS, so UA6's persist-before-display ordering is intact and stronger: state and history now save atomically together.
  4. generateActions' save becomes local-only (saveCore+saveMem, no sync arm) — see ruling R4. The actions still persist locally for reload; they reach the server on the next turn's POST or any page-hide flush.

Net: 3 LZ passes → 1; ~4 full stringify+setItem bursts → 1; 2 POSTs → 1. No format change, no skew risk, ships alone.

Accepted risk: a throw between applyMuts and the single save loses that turn's state to the last save — but the transcript pair is equally unsaved, so state and history stay CONSISTENT (strictly better than the UA6 failure class, where state saved and history didn't). The #14 pending-action recovery re-offers the turn.

4 · D2 — chunked transcript compression (f70 lever b): O(segment), not O(campaign)

Freeze the past; only compress the tail. The transcript is append-only except for four known mutation classes; exploit that.

transcript → {__lzc:{v:1, seg:SEG, segs:["<lz>", "<lz>", …], tail:"<lz>"}}
SEG = 256 entries per frozen segment (~140KB raw ≈ ~60KB compressed at mature-entry sizes)
segs[i] = LZ.compressToUTF16(JSON.stringify(entries slice i·SEG … (i+1)·SEG))
tail    = the remaining < SEG entries, recompressed per save (bounded work)

Per-save cost becomes O(SEG) — the tail — plus a cache lookup per frozen segment. Segment blobs cache on the existing WeakMap beside today's memo, keyed by the transcript array + segment index.

Rescue path (UA3) extension

If ANY segment fails to inflate, preserve the whole {__lzc} object verbatim under the existing per-campaign rescue key, start empty, shout — same semantics as today; restoreTranscriptRescue learns the form. Never partially inflate: a story record with a silent hole is worse than a loud rescue.

Skew-safe rollout (the inflater-first rule)

  1. Phase A (with D1): ship the {__lzc} INFLATER everywhere — producer nowhere. Zero behavior change.
  2. Phase B (next release): produce {__lzc} for localStorage only (device-local, same-build read/write — skew-free). The WIRE keeps {__lz}, derived from the same memoized whole (one pass, only when the debounce actually fires).
  3. Phase C (release after): flip the wire to {__lzc} — every deployed client has carried the inflater for a full cycle. Server stores the blob opaquely; no server change.
Non-goal: delta sync (uploading only changed segments) — needs server-side merge semantics and a new endpoint contract; the POST stays whole-blob. Segments make the CPU O(SEG); the wire stays O(campaign) per POST but there is now exactly one POST (D1) in the cheaper encoding (D3).

5 · D3 — the wire re-encode (f69): stop paying 1.33× to "compress"

OptionWire bytes vs plain JSONProperties
A — 6-bit ASCII repack {__lzb64} (recommended)~0.85× (vs 1.33× today ≈ −36%)Pure bit-repack of the SAME LZ bit-stream (no re-compression — O(n) shifts off the cached blob); synchronous, so the JP0-11 keepalive flush uses it too, and byte-count ≈ char-count makes the telemetry honest for free. ASCII survives every JSON/HTTP boundary.
B — CompressionStream('gzip') {__gz}~0.25×Async only — fine for the debounced POST, unusable in the sync flush (would need A as its flush fallback anyway); adds a second code path and a platform-API dependency. Deliberate LATER layer, only on measured need.
C — telemetry fix only1.33× staysHonest numbers, no diet.

Recommendation: A now, B never until measured. Implementation: lzPackWire(utf16)/lzUnpackWire(ascii) in compress.js (the 15-bit-per-code-unit stream repacked 6 bits/char); the sync payload builder emits {__lzb64} (or per-segment inside {__lzc} at Phase C); the tolerant inflater accepts it alongside every older form. localStorage keeps {__lz} — UTF-16 packing is the right shape for the UTF-16 quota, that win is real and stays.

Also in this commit: the 2M-char sentinel switches to real bytes via TextEncoder (JP0-11 already measures this way — reuse it); the stale comments claiming "server sync keeps the plain array" (compress.js header, state.js §comment) are corrected — both named by the f69 verifier.

6 · D4 — envelope clone scope-cut (f58)

Detach what the envelope can provably never write; share it by reference.

  • Before _w2Copy(worldState): pop worldState.transcript off, clone, reattach the SAME array to both the clone and the saved original. Reads (_speechFactNear) see it; commit and rollback both keep the one true array.
  • Fail-closed guard: after the envelope's handlers run, assert the shared array's length (and tail reference) is unchanged — a handler that appended treats the envelope as FAILED and rolls back loudly. This converts "provably never writes" from a comment into a tripwire.
  • Portraits (character.portrait, npcs[i].portrait, npcs[i].charSheet.portrait): same detach mechanism, one W2_CLONE_DETACH walk — safe even in theory because a string is immutable (a hostile write could only swap the clone's reference, never corrupt the original). Ship together with the transcript detach.
  • The memory clone is already the light half (f58 verifier) — untouched.

Net: kill-turn envelope cost drops from O(campaign) to O(state-minus-story); two-envelope responses stop doubling it.

7 · D5 — merge pre-image portrait policy (f44)

In the [NPC_MERGE:] pre-image clone, replace portrait and charSheet.portrait with {portraitOmitted:true, bytes:N}. One merge stops costing 100–1000× every other archive entry, forever, in the one blob with no LZ boundary.

The un-merge tradeoff, stated plainly (f44 verifier): when BOTH canonical and duplicate carry distinct portraits, the duplicate's image is NOT copied forward (the handler keeps the canonical's own) — so after this change an un-merge restores every fact, alias, event, and relationship, but that duplicate's image is gone for good. Recommendation: accept — portraits are regenerable art, not canon; the alternative (a separate capped portrait side-store for pre-images) buys little for real complexity.
  • f44(b) closes in the same commit: a worldState-only duplicate currently folds with NO ws pre-image archived at all (the push sits inside the if(memory.npcs[mgDupe]) branch) — archive the ws pre-image regardless.
  • No migration of existing archived pre-images (the #257 precedent: historical archives stand; the class stops growing). A dev census line in dev/item-bible-coverage.js-style tooling can report how many bytes legacy pre-images hold, for a later owner call.
