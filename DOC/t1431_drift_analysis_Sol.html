Immediately before t1431, the GM was still served the t1413 single-bed scene through RAG and had t1428–t1430 verbatim in the retained session tail. 4 · Root mechanism

  1. A split is durable until one exact tag clears it. tag_table.js:696–713 stores a split as charSheet.splitLoc. The only clearing path is explicit [PARTY_SPLIT:Name|rejoin]. A narrated reunion, a party-wide journey, a bare [LOCATION:], or many turns of co-presence cannot reconcile it.
  2. The stale values are old, not a t1431 write. Frizwick is already marked in the sea cave in the t1265 export and remains there at t1431. Daeris and Morwen are split at Sandpoint in t1385, then at Magnimar in t1411/t1431. The values survived hundreds of turns while the prose repeatedly placed the party together.
  3. The strict prompt trusts the stale field. helpers.js:352–356 treats any living party member with splitLoc.location as split. api.js:61–72 injects every such member under “SPLIT THREADS” on every turn with a “cannot perceive or assist” instruction.
  4. There is no age, audit, or contradiction detector. splitLoc carries no turn stamp. Unlike quests, schedules, conditions, moods, relationships, and arcs, it never asks whether a long-lived value is still true. This is a monotonic-state failure: once a missed rejoin leaves the field behind, it can persist indefinitely.
  5. The model resolves the conflict approximately. Recent prose momentum is strong enough that Sonnet keeps all four characters in the room, but the authoritative split pressure still favors separation. At t1430 it moves Morwen “across the room”; at t1431 it gives the two pairs separate beds. That is a plausible compromise between incompatible context, not reliable continuity.

The exported t1385 session provides a concrete missed-reconciliation case: all four characters leave Sandpoint together, and the GM emits only [LOCATION:Varisia - North Road]. Daeris and Morwen’s existing split fields remain at Sandpoint because the P5 contract deliberately says a bare location tag never moves a split member. The fiction reunites; state does not.

The reconstructed RAG block disproves that for t1431: it served t1413 directly, while the retained tail carried t1428–t1430. Missing description is an enabler, not the whole mechanism. Even with good episodic recall, authoritative state conflict can bend the scene.

7 · Proposed remedy

A. Split-state audit in the engine-note channel — primary fix

  • Add a turn stamp when [PARTY_SPLIT:] creates or reaffirms splitLoc.
  • After a modest age threshold, emit one engine note for the stalest split: if the character is still away, re-emit their current [PARTY_SPLIT:]; if they are back, emit [PARTY_SPLIT:Name|rejoin].
  • Put the audit in NOTE_BUILDERS, so it rides the newest user message. Adding more words to the existing system-prompt block is unlikely to help: that instruction has already lost to the GM’s own recent prose for hundreds of turns.
  • Reaffirmation refreshes the stamp; rejoin deletes the field. Audit one member per turn, silent in combat, with a recheck interval so a legitimate long split is not nagged continuously.
  • Do not auto-rejoin on name mention. Split-thread beats legitimately mention the absent character; prose alone cannot safely identify which thread a sentence belongs to.

B. Missing interior-description nudge — secondary hardening

For a sub-location occupied across a second turn with description:null, ask the GM through the same engine-note channel to emit one write-once [LOCATION_DESC:] containing layout, exits, and countable fixtures. This makes beds/windows/doors durable without mechanically promoting transient prose into canon. It would have pinned the room, but it would not repair stale split state.

C. One-time repair for this save

Clear charSheet.splitLoc for Frizwick, Daeris, and Morwen (or drive the same change through three explicit rejoin tags). The prose has established all three as present in the inn room. This report does not mutate the save; repair should be a separate, user-approved action.

  7. Description hardening: a settled sub-location with description:null produces one nudge; a populated description silences it permanently; pass-through locations do not create noise.

9 · Recommendation

Fix the stale-split lifecycle first, then add missing-description teeth as a separate hardening task. Retconning the current scene is optional and probably not worth it; the two-bed arrangement now has several turns of local momentum. The dangerous defect is not the furniture itself — it is that the engine has silently told the GM for hundreds of turns that the player’s three companions are elsewhere.
