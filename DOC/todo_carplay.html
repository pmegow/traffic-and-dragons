1feedbackHigh Toasts render behind the overlay: .tnd-toast z-index 400 < #car-overlay 500. Every failure/progress signal — GM-turn errors, voice-download progress, the v1.339 iOS-audio watchdog, quest offers — is invisible in the one mode where the screen is the only channel. Raise toast z-index above 500 (e.g. 600) AND route car-relevant classes (errors, download) into #car-status — toasts alone are too small to read while driving. 2stabilityHigh A failed GM turn strands the car on “Thinking…” forever, in silence: sendAction's error path (game.js:798) writes a retry UI into the story log — which the overlay covers — and never touches #car-status; nothing is spoken. Driver cannot tell failure from a slow turn. carMode branch on the error path: _carSetStatus("⚠ Turn failed — tap to retry"), map the next tap to retryLast(), optionally speak a short failure line via the native engine. Tap gains a state (retry-armed) — must reset on any success and never fire while busy; desktop error path stays byte-identical. MOpen
3layoutHigh Landscape mount is unusable — render-verified. At 812×375 the portrait circle (min(360px,60vw) at 3/4 aspect, flex-shrink:0) is 360×480px in a 375px-tall fixed non-scrolling overlay: status line and ALL THREE controls (⏮ 🎤 ⏭) are pushed fully off-screen; the × lands mid-screen. Overlay CSS only; re-verify BOTH orientations by screenshot after (the v0.28 lesson: render is ground truth). MOpen
4inputHigh Tap-to-cancel actually sends. _carTap on a live mic calls STT.stop() → rec.stop() finalizes recognition → onend auto-sends whatever was heard (car mode forces auto-send, stt.js:98) — while the status shows “Ready” as if cancelled. A mis-tap or passenger interruption fires an unwanted GM turn. Add STT.cancel() using rec.abort() (discards results, no auto-send); car tap uses cancel semantics. Desktop #mic-btn keeps stop()=finalize (dictation-into-field is its contract). Verify onend still resyncs state after abort and the "aborted" onerror stays silent (it already does). SOpen
5stabilityHigh No Screen Wake Lock. Zero wakeLock references in the codebase. When the screen sleeps mid-drive: STT dies, timers throttle, the loop stalls (narration may survive via the playback session, but the conversation is over until the driver unlocks the phone). navigator.wakeLock.request("screen") in showCarMode; re-acquire on visibilitychange (locks auto-release on hide); release in hideCarMode. Feature-detect (Chrome/Android, iOS Safari 16.4+). Battery draw is expected in-car (phone typically charging); MUST release on hide so normal play never holds the lock. SOpen
6bluetoothHigh A2DP↔HFP profile flapping. Auto-mic opens SpeechRecognition ~800ms after every narration (_carAutoMic); on Bluetooth car audio, opening a mic switches the route to the handsfree profile — output ducks/degrades, and many head units clip the first ~1s of the next narration when switching back. The tighter the loop, the worse the flapping. Add an “Auto-listen after narration” pref (default ON = today's behavior) so BT users can switch to push-to-talk; consider lengthening the delay. (No web API reliably detects BT routing — a pref beats a heuristic.) Pref must default to current behavior; pairs with rank 21 (continuous mode) — design them together, they pull opposite directions. MOpen
7platformHigh iOS Safari has no SpeechRecognition — Car Mode is output-only on iPhone (the primary phone platform): _carStartMic dead-ends at “Voice input not available in this browser”. The flagship car-trip feature can't take voice input where it's most used. Options: ① cloud STT adapter (MediaRecorder → provider, same adapter-table shape as PROVIDERS/TTS_PROVIDERS); ② surface a clear hint that iOS keyboard-dictation into the normal input works outside car mode. ① is the real fix. Cloud STT adds cost + a key surface + latency; the adapter-table shape keeps if(provider) branches out. Recognition audio leaves the device — note it in the UI. LOpen
8inputMed Auto-send has no quality gate. Any final transcript — a cough transcribed as “uh”, road noise as a word — auto-sends a real GM turn: API cost, a polluted narrative beat, ~30s of dead time. Gate: transcript < ~3 characters → #car-status “Heard ‘uh’ — tap to retry”, no send. Keep it minimal so legit one-worders (“attack”, “yes”, “flee”) pass. Desktop auto-send pref must keep identical behavior (gate only under carMode, or apply globally after a play-test). RETCON/retry already covers the escaped cases. SOpen
9feedbackMed Voice-download dead air. First Piper line in the car can trigger a 60–115MB download (progress toast invisible per rank 1) — minutes of silence, possibly on cellular, with no in-car indication anything is happening. When carMode, mirror download start/progress/done into #car-status (the progress callback already exists); consider a pre-flight check on entering car mode that warns if the selected voice isn't on disk. Reuses _piperEnsureVoiceNow's existing loud path — no new download logic; keep the (v1.340) truthful size in the message. SOpen
10freshnessMed Party bar / portrait / name never refresh after entry — _carUpdate() runs only in showCarMode. HP swings, companion joins/departures, and mid-game player switches leave the dots and hero stale for the whole drive. Tail-call if (carMode) _carUpdate() from syncUI() (ui-panels.js) — the one place every state change already funnels through. syncUI is hot: _carUpdate re-sets img.src each call → guard with a changed-check to avoid portrait flicker/decode churn. SOpen
11bluetoothMed Steering-wheel “play” while idle opens a hot mic. mediaSession play/pause both map to _carTap; when nothing is playing, tap = start mic + auto-send. The universal “resume audio” gesture becomes surprise voice capture (a passenger pressing play sends their sentence to the GM). Split the handlers: mediaSession “play” while idle → replay last narration (or no-op); mic stays on the on-screen tap only. Changes BT semantics only — on-screen tap flow untouched. Pairs with rank 18 (what “last narration” means). SOpen
12controlsMed ⏭ while paused starts the mic instead of skipping: _carNext tests isPlaying() only; a paused narration falls through to _carStartMic — mic over a half-finished, still-queued story beat. isPlaying() || isPaused() → skip. (skip() already handles a suspended ctx: _drain resets _paused.) None — skip semantics already correct downstream. SOpen
13persistenceMed carMode doesn't survive a reload. Any refresh or iOS tab-reclaim mid-drive lands in the full game UI — menu navigation at 70 mph to get back. Persist tnd_carmode_v1; init() restores the overlay when a saved game loads; expire the flag (>~6h) so a desktop session weeks later doesn't boot into car UI. Boot ordering (needs worldState); the × must always work as the escape hatch; interacts with rank 5 (re-acquire wake lock on restore). SOpen
14feedbackMed No audio acknowledgment. Between “Heard you…” and narration lies 10–30s of silence (GM latency + synth); eyes-on-road, that's indistinguishable from failure — which drives redundant taps and re-sends. Two tiny WebAudio earcons (oscillator blips, no assets): send-acknowledged and response-arrived. Pref-gated, car-mode-only by default. Schedule on the shared ctx so stop() kills them; keep them off the narration timeline (`_nextStart`) to avoid shifting speech starts. MOpen
15inputMed Recognition is cloud-backed (Chrome's STT is server-side): dead zones fail with a “network” error whose toast is invisible (rank 1) — status just says “Tap to speak”, so the driver retries into repeated silent failure. Route STT errors into #car-status in plain words (“No signal — voice input needs a connection”). Document the offline limitation beside the offline-TTS claim. None. 16correctnessLow Exiting car mode with the voice toggle OFF leaves the narrator running. speakResponse spoke because carMode was true; hideCarMode stops the primer but not the speech — “voice off” now audibly lying. hideCarMode: if (!TTS.isOn()) TTS.stop().
