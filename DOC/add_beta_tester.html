⚔ Adding a Beta Tester

Operator runbook · manual-entitlement era (TODO #288) · written 2026-08-30 · all of this becomes buttons when the #292 operator console ships

One-time setup — already done. Server deployed with the LLM gateway · provider keys set as Fly secrets · you (gh_24553571) are admin · GitHub and Google sign-in both live. Nothing here needs repeating per tester.

1Send the invite

Send the tester the game link and one sentence of instructions:

https://traffic-and-dragons.pages.dev

“Open it and hit Sign in with GitHub or Sign in with Google — then tell me you're in.”

Signing in is all it takes to create their account. They don't need an API key, and there's nothing to install.

Google-only caveat: if the Google consent screen was left in Testing mode (never published), a Google sign-in only works for emails you've added under Google Cloud Console → Google Auth Platform → Audience → Test users. GitHub sign-ins are unaffected either way. If unsure, have them use GitHub, or publish the consent screen.

2Wait for their signal

Until you grant a tier, any turn they try refuses with a friendly message: “This account has no active subscription yet — ask the operator for access…” — so they'll come tell you. (You'll usually also get an incidental #16 error-report email carrying that same message.)

3Get your admin token

In your own signed-in game window (desktop, the GitHub account):

  • Press F12 → Application tab → Local Storage → the game's origin
  • Copy the value of tnd_server_tok_v1 (a UUID)

It stays valid while you keep playing (30-day sliding expiry), so the same token usually works for weeks.

4Find them on the roster

PowerShell — paste your token into the first line, then run:

$tok = "PASTE-YOUR-TOKEN"; Invoke-RestMethod -Uri "https://traffic-and-dragons-server.fly.dev/api/admin/users" -Headers @{Authorization="Bearer $tok"}

The newest account with an empty tier is your tester. Copy their userId — it looks like gh_12345678 (GitHub) or g_1163603… (Google).

5Grant the tier

$tok = "PASTE-YOUR-TOKEN"; Invoke-RestMethod -Method Post -Uri "https://traffic-and-dragons-server.fly.dev/api/admin/subscription" -Headers @{Authorization="Bearer $tok"} -ContentType "application/json" -Body '{"userId":"PASTE-THEIR-USERID","tier":"tester","days":90}'

Expected reply: ok: True with the tier and an end date. days counts from today; re-running the command later extends from the new date.

6Tell them to reload

A hard refresh (Ctrl+Shift+R) and their next turn plays normally — served on the server's keys, metered against their allowance. They can check their own standing any time under File → Account (tier, turns used, access-through date).

When they hit the 300-turn ceiling: the game tells them plainly (“your story is safe, turns free up as older ones age out”) and you'll get the incidental #16 email. The window is rolling — turns older than 30 days stop counting automatically, so there's nothing to reset.
Their data is theirs, forever (ratified lapse policy): campaigns, characters, and libraries keep syncing and exporting even with no tier — only GM turns are gated.
