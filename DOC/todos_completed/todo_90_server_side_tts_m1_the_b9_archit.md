## Status / record

✅ **M1 SHIPPED (v1.435, 2026-07-24, built by Fable).** All five decisions ratified at build start: **D1** session-token auth (unconnected players keep the local ladder) · **D2** second Fly app **`tnd-tts`** (game server stays 256MB; TTS sized independently) · **D3** degrade toast once per session · **D4** Kokoro benchmark-gated (→ #91) · **D5** 3GB volume. **Server half** (server repo `tts/`, deploy `cd tts && flyctl deploy --ha=false`): Hono app, `POST /api/tts` {text, voiceId, rate} → audio/wav; warm `piper` daemon per (voice, rate) — spawn-per-request pays ~1-3s model load, so daemons persist with LRU cap 3 + 10min idle kill; the `--json-input` stdin protocol's stdout path-print is the completion signal, FIFO-aligned even across timeouts (a timed-out entry stays queued so later responses can't shift); 2 timeout strikes kill+respawn the daemon; voices download HF→volume on first use behind an allowlist mirroring `PIPER_VOICES` (the endpoint can't be used to fill the volume with arbitrary models); auth = proxy `/auth/me` with a 10min memo (one auth round trip per read, not per unit — known coarseness: a logged-out token works ≤10min, the gate protects CPU, not revocation latency); same per-IP rate limiting as the game server; `TTS_TEST_SECRET` ops lever (DEV_LOGIN_SECRET pattern) for deploy smoke tests — set, verify, UNSET. **Client half** (tts.js, off drift surface): `TTS_PROVIDERS.server` + `TTS_LADDER = server → piper → native`; `getEngine()` RESOLVES (connected+healthy → "server", else "piper" — offline devices byte-identical to #9 behavior, the 3 constant-piper engine tests pass unchanged); `_speakServer` = the `_speakPiper` unit loop with predict() → fetch (same splitter/speaker-maps/manual-WAV-decode/scheduler/backpressure/shared-epoch); ANY unit failure hands the WHOLE remainder down the ladder via the queue (the governor's handoff pattern — one timeout, never a per-unit stall crawl) + 60s retry memo; `prewarmServer()` health probe wakes the auto-stopped machine off the critical path; the governor never meters the server tier (no client work to budget) and keeps guarding the local tier forever; `storageAdapter.authHeader()` exposes the assembled header, never the raw token; Voice Settings shows a server-tier status line (off/active/degraded-with-reason). **Tests:** 810 green (+5 server-tier engine tests: resolution, D1 no-token, degrade window + backdated retry, D3 single toast, enqueue shape) + a 4-point SERVER TTS source contract in run-tests.js (zero-wasm, no governor contact, remainder handoff, ladder order). **v1.436 field fix (same day, from the user's first phone session):** the 🔋 governor latched because Fly parked the machine after ~2min idle and real turns idle longer — so nearly every read's first unit paid the measured 10.17s cold chain (machine boot + auth proxy cold-starting the GAME server too + daemon spawn + model load), 170ms past the 10s unit timeout → whole read degraded to local Piper → budget spent. Four-part close: ① fly.toml `auto_stop_machines = "suspend"` (RAM-intact sub-second resume — warm daemons + auth memo survive); ② `TTS.prewarmServer()` on the send gesture (game.js, beside the B10 recoverAudio tap) so the machine wakes while the GM is thinking; ③ first-unit timeout 15s (`SERVER_TTS_TIMEOUT_FIRST_MS`; units 2+ stay 10s); ④ diagnosability — ▶ Test auditions via the server tier when it's up (a local Test booted wasm + spent governor budget for nothing; no eviction prompt either, nothing downloads), and a connected page reading below the server tier now stamps a `tts-server-skip` crumb + console.info (silent-local reads were climbing the budget with no signal — the no-silent-failures gap). Contracts ⑤⑥ pin the Test routing + the send-tap prewarm.
