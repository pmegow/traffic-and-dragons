## Task

**Text to speech — Piper-only, with per-speaker voice assignment. REWORKING the Voice Settings (2026-07-20, user).** Car audio is a primary use case. **Direction change (design in discussion — see below):** ① **REMOVE Cartesia** (too expensive to be viable — user call; strip the provider + its UI). ② **REMOVE Native as a user-facing engine choice** — Claude's recommendation (user deciding): KEEP it as an automatic SILENT fallback when Piper is unavailable (Piper needs a 60–115MB download + WASM + OPFS; a total-failure-if-Piper-fails is worse than a fallback), but delete the whole "Voice engine" 3-radio section — **Piper is THE engine**, so the picker is noise. ③ **Expand the voice catalog:** `PIPER_VOICES` (tts.js) hardcodes 8 today; grab ALL English Piper voices (en_US + en_GB, HF `rhasspy/piper-voices` manifest) and build a **voice-audition satellite player** so the user picks ~25 to keep. ④ **New UI (from the user's marked-up mock):** the "downloaded voices" 4-slot LRU becomes a per-ROLE **ASSIGNMENT list** — each row = [downloaded-voice dropdown] → [role dropdown]; roles start as **Narrator + Party member 1–N**; a **"+ add voice" button** adds rows (5 to start, no cap assumed). ⑤ **THE OPEN ARCHITECTURE QUESTION — hooking voices to speakers (design first, "or at least figure out HOW"):** narrator prose is already solved (one voice for all narration); per-character dialogue needs the TTS stream SEGMENTED by speaker. Three approaches, tradeoffs: **(A) GM-tagged dialogue** e.g. `[SAY:Morwen]…` — accurate, fits the tag architecture, BUT drift surface (new tag → Fable) AND requires TTS to read the RAW response, not `cleanTxt`'d prose (real plumbing change); **(B) heuristic quote-attribution parse** ("'…,' Morwen said" → her voice) — zero prompt change, but English attribution is genuinely unreliable (pronouns, unattributed lines, interleaving) → misvoicing; **(C) LLM post-pass** returning speaker-segmented spans — accurate, but +1 call + latency every turn. Also decide: does "Party member 1" map POSITIONALLY (Nth in party) or per-NAMED-character? 



**What shipped before the rework (retain what still applies):** GM narrator voice works; Piper local/offline (#41); native voice picker (v1.77) — the picker UI goes, but the native-voice resolution stays for the fallback. 



**⑨ VOICES NEED A GENDER ATTRIBUTE (user report 2026-07-22):** an NPC coming out sounding like a longshoreman breaks the scene. **The concrete gap:** gender exists on BOTH sides but never as matchable data — characters carry `gender` ("M"/"F"/"NB") on the v10 schema, and every curated voice states it, but ONLY inside the human-readable `label` string ("Alba — UK female", "HFC male — US"). `PIPER_VOICES` entries carry `id/label/size/speakers/blurb` and **no gender field**; `tts.js` contains the word "gender" zero times. Nothing can filter, sort, warn or auto-pick. **Scope:** ① add `gender` to each `PIPER_VOICES` entry (transcription from the labels, not judgement — mark the genuinely ambiguous ones as such rather than guessing); ② the sheet's Voice dropdown groups/orders by the character's gender so sensible options are not buried among 19; ③ decide the MISMATCH behaviour — allow silently or soft-note, but do NOT hard-block, since deliberate miscasting (disguise, possession, non-human) is a real use. **Watch the narrator fallback:** an unassigned character speaks in the NARRATOR voice (`characterVoiceId` → `resolvePiperVoice`), one fixed voice for everyone, so every unassigned NPC of any gender already sounds identical — gender-aware DEFAULTING may matter more than the picker does, and is the likelier cause of the reported case. **Do this WITH ⑦, not twice:** libritts_r holds 904 speakers in the 75MB download already on the device, so gender-tagged speaker indices would give varied, appropriate casting for every NPC at zero extra download.

**BUILT v1.406 — the (C) LLM speaker post-pass.** Design ratified with the user 2026-07-21 and shipped the same day; every decision below is as built. TLDR: after each turn, a cheap LLM call says who speaks which sentence, so dialogue narrates in each character's own voice. **Measured facts that shaped it:** `speakResponse` fires at game.js:832 BEFORE `generateActions` at :833, so narration waits for nothing today — "run it concurrently with the suggestion call" would ADD a wait, not hide one; time from `speak()` to first audible sample is **5,920ms** warm (voice cached, WASM compiled); `_speakPiper` already calls `mod.predict` PER UNIT (tts.js:1067) under `PIPER_MAX_AHEAD_SEC`=25 backpressure, so per-unit voice is a one-line change, not a rearchitecture. **Ratified:** ① **Blocking with a fuse** (user call, against the no-block recommendation): narration waits for the map, hard ceiling ~4s, then speaks regardless — an unbounded wait would turn one hung request into a silent turn. ② **Contract = unit INDICES, not text spans** (supersedes the original `{speaker,text}` shape): the model gets the numbered `splitSentences(clean,null,true)` units — the exact units the synth loop will use — and returns `{index: speakerName}`; index binding removes the substring-matching failure mode, where a paraphrased span silently mis-voices. ③ **Only characters with an explicitly assigned `voiceId`**; the prompt carries just those names, and the call is SKIPPED entirely when none exist or the response has no quote marks — non-users pay nothing. ④ **Tiny standalone prompt** on the active provider (no world state, no cache reuse — mechanical attribution, not creative work); new `kind:"speakers"` bucket in `recordUsage` so the cost is attributable in the Usage modal. ⑤ **PERSISTED PER TURN ON THE TRANSCRIPT ENTRY** as `sp:{n,s}` — additive field stamped by `logTranscript`, exactly the shape of RAG's existing `e:{n,l,q}` ("additive fields — no schema bump", §8b), so it does NOT engage the transcript-is-sacred decree (that bars trimming/capping/restructuring, i.e. loss). This makes the ALREADY-SHIPPED per-message 🔊 replay button (ui-shell.js:191, attached on transcript rebuild at ui-boot.js:322) re-speak ANY past turn as first heard, on any synced device — and it collapses the `worldState.lastNarration` copy: one home, no desync to engineer around. Footprint accepted by the user without measurement: only dialogue-bearing entries grow, ~50–70 raw chars on a ~1,200-char entry (~5%, less post-LZ since names repeat). ⑥ **Staleness guard (the trap):** indices bind to splitter output, so a future `MAX_UNIT`/pause-tier change would silently re-index every stored map = confidently WRONG voices on old turns. `n` = unit count at write time; if `splitSentences(text).length!==n` at replay, drop the whole map and narrate flat. ⑦ Story turns only — Table Talk is the single-voice help desk. Resolution via `resolveNpcName` → `TTS.characterVoiceId`. Output post-process, no applyMuts/memory/prompt contact → Sonnet tier.
