## Task

**The `*_bible` system — canonical capability/entity references the GM and players both use.** **2026-07-04 play finding — this is an anti-drift problem, not just a UI nicety: spell capabilities drift wildly in play. Observed: *Message* was line-of-sight when first used, now its distance is limitless.** With no canonical entry, the GM re-improvises each spell's rules from its name every time, and compressed memory carries no correction. The bible must be **GM-authoritative**: inject the canonical entry into the prompt on cast/use (same re-inject-from-data pattern as the quest block, char sheet, and `[LOCATION_DESC:]`). **#8 merged in:** two consumers, one data source — ① GM prompt injection on cast/use (anti-drift), ② player-facing click-card/tooltip on spell & inventory names (old #8). 

**Design converged 2026-07-07 (naming + schema):** 

• **Nomenclature (locked): `<domain>_bible`, singular** — `spell_bible`, `item_bible`, `creature_bible`, `profession_bible`. Viewer page = `bible_study` (satellite HTML, not index.html; read-only; its render IS the in-game player card — one render, two hosts). Prefix names the domain so "where are the spells?" never happens; a viewer/injector iterates all `*_bible` registries uniformly. **`library` was rejected — collides with the existing Character Library** (`listCharLibrary`/`showCharLibrary`). *(Clarity above Brevity: the existing bare `library`/`bestiary` names are the anti-pattern we're correcting here.)* 

• **Format: structured JS constant in its own file(s)** (`bible.js` or per-domain), loaded via `<script src>` (file://-safe, no build step) — NOT markdown (the engine reads it per-field; prose would defeat the tight-canon injection and force a runtime MD parser). Keyed by **base name** (parenthetical stripped) so existing `char.spells[].nm` strings and the `[SPELL_USED:]` base-name matcher keep working — pure lookup overlay, no refactor of how spells are stored. 

• **Entry = one unified "capability" shape** (spells and abilities have **no intrinsic difference** — validated 2026-07-07). Cosmetic `kind` tag for modal grouping only. Two REAL structural fields: **`cost`/recharge** (`at-will` / `N-day` / `slot:tier` / `1-rest` / `passive` — unifies cantrips, abilities, racial 1/day, leveled spells; also the P10/R1 recast guard) and **`isMagical`** (bool — the one genuine spell-vs-ability divider: dispel/counterspell/antimagic/detect-magic susceptibility; **authoring rule: `true` if it would light up under Detect Magic / be targetable by Dispel Magic**). Drift-pinning fields: `range`, `targets`, `duration`, `effect`, optional `dice`/`save`/`concentration`/`tags`. GM injection uses a tight line built from these; the card renders them. 

• **Static base + emergent overlay:** authored canon in `*_bible.js`; GM-invented spells/items get a **write-once `[SPELL_DEF:]`/`[ITEM_DEF:]` tag** (LOCATION_DESC pattern) filing a per-campaign overlay in worldState/memory, merged over the base at lookup. 

• **No editor for v1** — hand-authored JS like `SPELLS`/`DEFAULT_RULES`; `bible_study` gives readability, editability stays hand-edit; a real editor waits until blueprint-bundled bibles create demand. 

• **Bestiary reconciliation:** `creature_bible` must ABSORB the existing `worldState.bestiary` (blueprint `creatures` → BESTIARY block), not become a second monster home. 

**MVP slice:** `spell_bible` only, base-name-keyed, injection on `[SPELL_USED:]` + player card (fixes the drift immediately) → then fold in abilities → `[*_DEF:]` write-once tag → other domains.
