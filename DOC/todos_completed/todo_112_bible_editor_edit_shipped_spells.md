## Task

**Bible editor: edit shipped spells straight from the card — ✎ Update Bible.** TLDR: balancing classes means adjusting the spells themselves, but the ✓-badge capability card was read-only — fixing "Toll the Dead" meant leaving the class view, opening capability_bible.js, finding the entry, editing, saving, coming back. Now the card carries **✎ Update Bible…**, which opens the existing attribute form pre-filled with the shipped entry (keyed lowercase, so the capitalized-key warning never fires on an entry you didn't rename); its save button reads **Update Bible** and writes capability_bible.js SURGICALLY through the file's OWN handle (`FS_CAP_KEY`, IndexedDB-persisted like the main one; first use picks the file once) — the class bible stays the tab's open file. The file is read fresh in the same promise chain as the write, so the changed-since-read window that plagued the main Save cannot open; the minimal-diff serializer keeps comments and untouched entries byte-identical; the in-page `CAPABILITY_BIBLE` global refreshes on success so badges/cards/tooltips show the new values immediately. Failure semantics: the form only closes on a SUCCESSFUL write (`capForm` savers can return false to own their close), every failure is a loud alert, and the user's edited values survive in the open form. (User request 2026-08-01.)
