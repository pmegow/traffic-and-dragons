## Task

**Reliable consumable drain — the durable fix #50a's doc line couldn't deliver (open design problem for a fresh Fable pass).** Recurring symptom: consumables narrated as spent never leave the sheet. Live evidence — the t582 Runelords save (`Rise_of_the_Runelords_Ammut_t582.tnd`): blasting charges stuck at **x4** since t455 (~127 turns) through repeated detonations; at t569 a charge is wedged into the stairs and at t570 another is thrown and detonates ("the blast comes up through the floor like a fist"), yet the sheet never moves off the exact count the player named at t531. **Proven NOT an engine bug (2026-07-13):** loaded the real engine against the actual t582 inventory — `Blasting charge x4` drains correctly to x3/x2/x1 for every normal tag form (`Blasting charge`, plural `Blasting charges`, lowercase); the only no-op is a parenthetical qualifier (`Blasting charge (thrown)`). Count pristine at x4 ⇒ **zero `[ITEM_LOST:]` ever emitted** = model under-emission, the #50a class recurring. **Why the obvious fix is already spent:** the stable prompt rule (tag_table.js:47) LITERALLY names "a charge detonated" as the trigger and was ignored anyway — this is a model-adherence ceiling during fast action scenes, not a missing instruction, so strengthening the nag won't carry it. **Design space explored with the user (all rejected here, recorded so the Fable pass doesn't re-tread):** (a) per-turn auto consumption-check that reads the GM narration and emits the tags — **rejected: a 2nd model mutating authoritative inventory 500×/campaign unattended is the drift surface firing constantly; false-positives remove items that were reached-for-not-used**; (b) reading PLAYER INPUT instead of narration — rejected: input is intent, not outcome (a thrown charge may fizzle); (c) periodic auto-run of the existing Sync inventory audit (#50a option 1) — same drift risk, just less often. **Cost context (t582 telemetry): main GM turn ≈4.15¢ dominates (88%); a suggestion-sized side call ≈0.26¢/turn (~5%)** — so cost is not the blocker, correctness/drift-containment is. **The unsolved question for the Fable pass:** a mechanism that closes the ghost-consumable gap WITHOUT a hallucination-prone second model writing state every turn — candidates to weigh: a deterministic player-driven "use/spend item" sheet affordance (no model in the loop for player-initiated consumption); a tighter, cheaper detector scoped to only items whose names appear in THIS turn's narration (bounded blast radius); or a confidence-gated correction that only ever DECREMENTS a consumable the sheet lists and the narration explicitly spends. ⛨ drift surface (inventory write path + tag docs) — design first, present before building. See the #50 row for the full inventory history and the shipped #50a/b/d work. **✅ DESIGN RESOLVED + SHIPPED (Fable, v1.308, 2026-07-16): the house pattern — engine detects, GM decides.** `detectGhostConsumables` (game.js, the #40/#46/#61 post-pass site — ZERO parser contact): an inventory entry is a consumable candidate if counted (" xN", N≥2 — the t582 form) OR base-name matches `CONSUMABLE_RE` (globals.js; ammo deliberately excluded from the lexicon, the xN path carries stacks); flagged when its **HEAD NOUN** appears in the turn's player action or GM narration with no ITEM_LOST/COMPANION_ITEM_LOST in the same response (head-noun matching is load-bearing: the t582 narration said "a charge is wedged", never "Blasting charge" — full-name matching misses the real case; the looseness is priced in below). Queued (bounded 6, deduped) → `buildConsumableNudge` (api.js, 9th NOTE_BUILDERS entry): one item per turn, asks the GM to check its OWN narration and emit the battle-tested tag "or leave the sheet alone — do NOT invent a consumption" (the false-positive escape, the C-scenario-validated soft-nudge shape); cooldown latch `CONSUMABLE_NUDGE_COOLDOWN`=6 written on fire (an ignored nudge means "not spent" — re-nagging would railroad a false decrement); combat-silent WITHOUT consuming. **Pre-review (confidently resolved, recorded per the amended clause):** companions included (same class, same tags); no spend-verb gate (soft wording + cooldown bound the loose match instead); the player-driven "use item" sheet affordance deferred as complementary UX (doesn't fix the observed class — the player didn't notice the ghost either).
