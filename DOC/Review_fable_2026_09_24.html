5. Suggestions

Each one had to answer "does this improve the product, and how" — if it was only a change, it was dropped. Three passed; the dropped ones are named at the end so they are not re-proposed.

S1 · /health reports the server version

Improves Operability and honesty. Today the question "which server is running" needs a Fly release number and a receipt file that can lapse (F3); with {"version":"1.5.3"} in the health body it is answered by one request, the same way APP_VERSION answers it for the client, and the client's Connect modal could show both side by side.

Cost One line reading package.json at boot; the health workflow already fetches the endpoint.

S2 · Warm the server before the first turn after a long idle

Improves Reliability of the first turn after a break — the owner's own field symptom ("first GM call after a swap failed as CORS, retry got 200"). With auto_stop_machines = "stop" and min_machines_running = 0, the first request after idle can meet Fly's own cold-start reply, which no in-app header decorates. A fire-and-forget GET /health when the game screen opens (and again when a session resumes after PREVIOUSLY_AFTER_MS) starts the machine while the player is still reading, so the GM call lands warm.

Cost One request per session open, nothing when the machine is already up. It deliberately does not touch callGM's transient set (a completed-but-unreadable reply may already be billed, so the transport must not auto-retry a network failure). The paid alternative, min_machines_running = 1, buys the same outcome for a VM's monthly cost.

S3 · "Consult the story instead" on the item-canon proposal

Improves The recovery path the owner walked last night: a proposal that reads "effect: N/A · value: 800 gp" (any healed or thin proposal) currently needs Decline → open the sheet → find the item → Define. One button on the proposal modal — Decline and consult the story — runs the existing defineItemFromStory for the same key, so the GM's own account of the item (Morwen's identify scene) lands in one tap. The confirm queue, the write-once rule and the review-call whitelist are untouched; it is the #435 button on a different host.

Cost Thin DOM wiring over an existing function; one test for the wiring.

Considered and dropped (changes, not improvements): switching the injected ITEM CANON line from effect: … to effect=… (the parser now absorbs both forms; prompt churn for no player-visible gain); widening the idiom list from the candidate scan (F8 — false positives); a batch "define every undefined item" action (N paid review calls for a list the player has not asked about); deep-linking the Register readout's sheet finding to the character editor (a hop saved, nothing learned); the semantics-preserving snapshot skip from #421 (2 ms nobody perceives).
