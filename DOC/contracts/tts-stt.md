### tts.js

Status: ✅ Active

Text-to-speech: `TTS` module with a `TTS_PROVIDERS` table (mirrors the LLM `PROVIDERS` shape): `server` / `piper` (local WASM, offline, $0 — #41; vendored at `/vendor/piper/`, voices cached in OPFS) / `native` (browser speechSynthesis). Self-hosting is why the #84/LiveKit objection doesn't apply ([DOC/Research/liveKit_findings.html](DOC/Research/liveKit_findings.html)). The per-item **downgrade-to-native** ladder survives below all of it (`_piperOk` can drop ONE item without changing the engine); the work-budget governor meters ONLY the local Piper tier and remains the offline tier's guardian forever. Shared text-prep (`normalizeForTTS`/`splitSentences`), queue/scheduler, voice bank. **NPC casting (#174):** every roster NPC auto-casts from the starred bench on first speech (sheet gender → pronouns → full bench); the stable pick persists on the NPC record until a generated sheet inherits it. **Gemini tier (#41, v1.646; opt-in, default OFF — bills the player's own gemini key):** `TTS_LADDER` is now `gemini → server → piper → native`; Google prebuilt voices via `generateContent` AUDIO on `gemini-3.1-flash-tts-preview`, consecutive same-voice units GROUPED per call, narrator/direction prefs + ▶ Test audition, degrade window 60s. **#41b (v1.653): the synthesis CONVEYOR** — `_geminiConveyor` runs up to `GEMINI_TTS_PREFETCH`=3 groups concurrently, delivers strictly in order (`started−taken<depth` is THE bound: memory, quota burst, and skip-waste together; abort-on-skip cancels in-flight billing); `GEMINI_TTS_FAST_START_CH`=220 caps group 1 for the cold open; `_geminiTimeoutMs` scales deadlines with group length. **#41c (v1.654):** 429s are QUOTA windows, not blips — patient backoff [5s,15s,30s] honoring the body's `RetryInfo.retryDelay`, absorbed by the conveyor's own runway; skip-aborts recognized mid-wait (the deadline timer self-identifies; #41d makes the sleeps themselves abort-raced) so long retries can’t bill a dead read. **#41d (v1.655):** a RetryInfo hint over 45s = a CLOSED quota — degrade immediately with Google’s number and extend the degrade window to it (capped 10 min) instead of re-probing every 60s. **#41e (v1.656):** prime-the-pump — the first schedule holds until the opening seam is covered (group 2 landed / 8s contiguous lead / 8s hold cap), so a short opener + early voice change can’t start-then-hang. **#41f (v1.659): the in-family MODEL LADDER** — `GEMINI_TTS_MODELS` = 3.1 → `gemini-2.5-flash-preview-tts` (Google documents ONE shared 30-voice list, so a fall keeps the entire cast; 2.5 is half the paid price). Free-tier quota buckets are PER-MODEL: a closed-quota 429 closes ONE bucket (per-model memo, honors Google's hint clamped 60s–10min, never shrinks) and the SAME group retries on the next rung mid-read; later fetches skip closed buckets without probes; only an all-closed ladder degrades the engine, window sized to the EARLIEST reopen; ▶ Test/opt-in clear the memo. Battery: dev/tests-41f-gemini-model-ladder.js (scripted fetch, in run-standalone-suites). Streaming remains the deliberate later step (conveyor slots become streams — rung 0 only; 2.5 can never stream).

**Fable audit 2026-09-18, section F (F8/F10/F11/F12):** the **effective** ladder is `inworld → speechify → openai → gemini → server → piper → native` — `TTS_LADDER`'s literal plus the `unshift` one line below it, which the run-tests pin now composes and matches against that documented order outright (it used to read the literal only, so the four cloud rungs were never pinned at all). **Every AudioContext.resume() is observed (B39, 2026-09-21):** the app runs TWO main-page contexts — tts.js's narration context and sound.js's earcon context (ambience plays on the latter through `Sound.context()`) — plus stt.js's mic context. B10 root-caused "Failed to start the audio device" to a `resume()` whose promise nobody handled and fixed only tts.js's site; the earcon and mic sites kept a bare `try{ctx.resume();}catch(e){}` (a synchronous catch cannot see an async rejection), and the same fingerprint returned as B39 from every toast, gesture or not. Now ONE observer, `resumeObserved(ctx, tag, onRefused)` (helpers.js): calls `resume()`, attaches a rejection reporter (a tagged console warn + a `ctx-refused` crumb), runs the owner's `onRefused`, and returns the SAME promise — never a bare `.catch(){}`, which would silence the only signal this class has. tts.js keeps its doom/refusal bookkeeping through it; sound.js dooms a refused context, `_ensureCtx` closes it and mints a fresh one on the next request (monotonic-resources rule), dispatches `tnd:audio-refused`, and exports a non-creating `Sound.state()` that the crash-report diag line appends as `snd=`; ui-ambient.js re-arms on that event (drops its controller, which closed over the old context, clears `unlocked`, so the next tap runs `unlock(true)` on the rebuilt context). The pin `B39 resume observed` (run-tests) scans every audio file for a bare `.resume()`; the flow is `dev/tests-b39-resume-observed.js` (real helper + real Sound against a fake refusing context) and `dev/sabotage-b39-resume-observed.js`. Device verification (iOS after an interruption) is the open item.

### stt.js

Status: ✅ Active

Speech-to-text input: `STT` module with **two independent paths**. ① **Native** — Web Speech API (`webkitSpeechRecognition`, zero-dependency): Chrome/Edge desktop + Android Chrome; NOT Firefox; iOS Safari has NO SpeechRecognition at all. ② **Cloud fallback** — when native is absent AND an OpenAI key is on file, `MediaRecorder` captures the utterance and OpenAI transcribes it (#113 §4: `gpt-4o-mini-transcribe` primary, loud `whisper-1` fallback; `sttBiasPrompt()` roster/place/quest vocabulary on every request; WebAudio silence endpointing 1.5s/45s). **This is what makes the iPhone Safari / Car Mode path work** ([history](DOC/CLAUDE_HISTORY.md#sttjs--the-stale-doc-lesson-84)). A fully separate code section below the native one, so native behavior stays byte-identical wherever native exists; `isSupported()` gates the mic button on EITHER path. Both paths run the final transcript through **`sttCorrectNames`** (helpers.js) — roster-phonetic correction for fantasy proper nouns. Prefs: auto-send (`tnd_stt_autosend_v1`), Car Mode auto-listen (`tnd_car_autolisten_v1`, default ON) — recognition language is the constant `STT_LANG` = "en-US" (audit F7 retired `tnd_stt_lang_v1`: nothing ever wrote it, so every read returned the fallback; a real language picker brings a setter, a menu row and a line here back together). Notifies Car Mode via global `carNotify(kind,text)`, always behind a `typeof` guard. ⚠ **Transcription cost rides the PLAYER's own key** — decisive in declining LiveKit. **#77 confirm gate (v1.548):** per-utterance confidence (`sttLogEvent` ring, read via `sttLogAll()`) feeds `sttSuspicion` (helpers.js), gating the AUTO-SEND path only — Car Mode speaks "I heard: … — send it?" with spoken yes/no/redo (`parseConfirmCommand`; the confirm interceptor sits ABOVE carVoiceCommand/busy-park/<3-char gates), non-car auto-send holds + amber-flags the field; File ▸ Admin ▸ 🛡 toggle, default ON; nothing touches sessionLog/transcript until confirmed. Invented tags (the [MANA:-1] leak) are display-stripped by cleanTxt's unknown-tag catch-all

**Fable audit 2026-09-18, section F (F2/F3):** `cancel()` and `stop()` are immediate through the whole cloud lifecycle, including the **acquisition window** — from `_cloudStart` until `getUserMedia` resolves there is no recorder and no stream, so both used to be no-ops and the permission promise opened the recorder *behind* the cancel, holding the mic and the #19 playback session (which silences ambience) until the 45s backstop. `_cloudCancelAcquisition` bumps the generation so the pending `.then`/`.catch` reads stale and stops every track it receives, and releases `_capture(false)` on the spot. The #77 `_confirmPending` is Car-Mode-only state: it is cleared by `cancel()` (an explicit discard) and by `STT.clearConfirm(reason)`, which `hideCarMode` calls — an unanswered "send it?" must never outlive its overlay, because `_applySendPolicy` checks it above everything and would consume the next desktop dictation as the answer. It is deliberately NOT cleared by `stop()`: stop is how the cloud path DELIVERS the spoken answer ("tap when done"), so clearing there would break the iPhone confirm loop rather than protect it. Every clear logs a `console.debug` with the discarded text.

Character sheets and sheetless roster NPCs may carry `speechifyVoiceId` (primary actor), while existing `voiceId` remains the Piper backup, including composite speaker suffixes. The character-slot registry supplies UI labels, catalogs, tests and assignment fields. Campaign creation assigns unfilled player/companion slots randomly by gender; NPC sheet generation inherits existing pins before filling missing slots and ignores model-authored voice settings. Speechify uses the saved catalog; if no matching catalog is available, primary stays automatic. Piper uses matching stars, then the shipped speaker bench. Existing nonempty pins are preserved. Sheet controls save immediately like the old character voice control. Speaker maps keep numeric Piper IDs and add `providers.speechify` by unit for explicit primary pins; stored SAY names and replay count checks are unchanged. Cloud failures rebase only unread numeric speaker IDs for Piper and preserve composite IDs. Player-controlled settings ride ordinary sheet save/export/import. **Fable review 2026-09-11 (v1.907):** ONE gender predicate — `castGenderMatches` (tts.js) serves the sheet filter, the creation assignment and the auto-cast pool; M and F match exactly, NB/ANY/unknown see the whole bank (an empty picker beside an unfiltered auto-cast was a silent failure). At speech time `pinAutoCastVoices` fills a missing Speechify pin BEFORE the Piper guard, so a legacy character with a backup still gets a primary. A failed cloud AUDITION never hands a remainder to the read queue; Stop empties queued-but-unsent items. The backup list names its empty state ("No matching actors") like the primary.

**Per-line mood (#458, v1.1001 — owner ask 2026-09-25):** `[SAY:Name|mood]` — the optional second field is HOW that line is spoken, a short phrase gated by ONE pure function, `sayMoodShape` (helpers.js: letters, spaces, commas, hyphens; ≤ `SAY_MOOD_MAX` = 40 after whitespace collapse; anything else returns "" and the caller drops it with a console line, the speaker binding untouched). Not in this build: a narrator mood (`[NARRATE:mood]`) and inline non-verbals mid-line (the strip would leave bare bracket words in the story pane). Battery: `dev/sabotage-458-say-mood.js`. **#462 (v1.1003, owner 2026-09-25 — Village t135, `[surprised, laugh]` never laughed):** Inworld's non-verbal sounds are STANDALONE tags, so a sound sharing a bracket with a mood reads as steering and is lost. `INWORLD_SOUNDS` (tts.js, ONE table beside the entry as `sounds`: laugh, giggle, chuckle, sigh, breathe, gasp, clear throat, cough, yawn, sob, groan) and `_markupPrefix(m, mood)` split the mood on commas: every part naming a sound becomes its own bracket (case-folded, fired once, in the order written), the remaining words fold into ONE steering bracket in Inworld's phrasing — `surprised, laugh` → `[speak surprised] [laugh] `, `laugh` → `[laugh] `, `amused` → `[speak amused] `. Steering first (it carries forward), then the sounds, then the text. **Car Mode spoken commands (#410, 2026-09-14):** every command is matched as the WHOLE utterance after filler stripping (`parseCarCommand`, helpers.js) — a substring match would eat real turns. Vocabulary: pick by number/ordinal · repeat / options · repeat everything · roll · never mind (undo the last item move) · wrap up · previously / recap · **pause / GM pause** · **resume / unpause / GM resume / GM continue** (bare "continue" is an action, never a command; "stop" was rejected as too common). What pause does is the pure `carHoldDispatch` table: while the narrator plays it is the TTS pause toggle (as the tap and the steering-wheel button); while the mic is open it HOLDS the session — the auto-mic loop stays closed until resume or a tap. The executor in ui-carmode.js dispatches a `tnd:car-intent` CustomEvent (`detail.kind` = pause | resume) fired ONLY by player-facing controls, never by internal `TTS.stop()` cleanup; ambience (L7) subscribes there. The mic is closed during narration, so a spoken pause cannot interrupt a playing narrator — that remains the tap.

**Fable audit 2026-09-18, section F (F1/F13):** `hideCarMode` fires a **resume** intent unconditionally — closing the overlay is a player-facing release. Clearing `_carHeld` was never enough: the hold also lives in every subscriber that heard the pause (ambience latches it and clears only on a resume intent or the unlock button, which a normal session never shows), so exiting after a spoken "pause" wedged the bed OFF until a page reload. The deferred mic opens (800 ms after narration, 500 ms for a confirm answer) re-read `_carHeld` and `TTS.isPlaying()` at fire time and `_carStartMic` refuses under both on its own — 800 ms is long enough for the driver to say "pause" or for the next read to start, and a mic opened on top of either transcribes road noise or our own narration. Both handles, plus the 300 ms options poll, live in `_carMicTimer`/`_carOptTimer` and are revoked by `_carOptReset()`, which `hideCarMode` now calls: no timer outlives the overlay.


**#19 second pass (2026-09-22, v1.972) — the Bluetooth handoff is instrumented, the primer is never silent, transport is idempotent.** The car verification of v1.943 came back "reaches the stereo, drops in and out rapid fire" with no console to read, so the handoff now writes to the #16 crumb ring: `audio-session from>to` on every REAL type transition (a same-value set is silent), `ctx-state <state>` on every state change of the narration context (one per state per 2 s), `read-route <why> ol= bl= st= as= cap=` at every read start (`outputLatency`/`baseLatency` in 5 ms buckets, the context state, the session type and the capture flag; identical consecutive fingerprints coalesce, and the first read after a capture end is always written), and `media-action <kind> <state> #n` for every Media Session command Car Mode receives (per-kind 2 s window; the count keeps rising, so a spamming head unit reads as one crumb with a big number). The primer buffer is full-scale noise under its 1e-4 gain (−80 dBFS) — never digital zeros, which some head units mute on. Car Mode's transport is IDEMPOTENT (`_carTransport`, ui-carmode.js): `play` resumes only a paused read, `pause` pauses only a playing one, a redundant command is a no-op, and an idle `play` replays the last narration only when no turn is in flight and the mic is closed; the on-screen tap keeps its toggle. The capture→`playback` timing is deliberately unchanged until the crumbs say which mechanism is live (the TODO #19 row ranks them). Batteries: `dev/tests-19-audio-session.js` (12 groups) and `dev/tests-19b-carmode-transport.js` (8 groups), both written failing-first.

**#19 third pass (2026-09-22, v1.973) — position state is ONE push per read.** The owner's same-day result that plain narration over the car's Bluetooth stutters exactly like Car Mode's demoted the mic-cycle and transport mechanisms and pointed at the one thing every WebAudio read did on a timer regardless of mode: `_armPosState` pushed `setPositionState` every 2 s with a growing duration, and on iOS each push is a Now Playing metadata update, i.e. an AVRCP notification some head units answer by glitching their decode (Apple throttles apps that push too often — "Application exceeded audio metadata throttle limit" — and says push only when the item changes). Now `_armPosState(ctx, text)` pushes ONCE at read start — duration estimated from every queued character at the current rate (`POS_CHARS_PER_SEC` = 14 at rate 1.0), position 0, playbackRate 1, the OS extrapolates — `_clearPosState` pushes the zero state once at read end and only if something was pushed, and no timer exists. Cosmetic cost: a long read's scrubber may end early. Pinned by the `position state is ONE push per read` group in `dev/tests-19-audio-session.js`.

**#19 fourth pass (2026-09-23, v1.974) — the Car Mode entry: warm the mic, read the scene, jump to the options.** Owner ruling: "When car-mode starts, just read the current scene, and jump to options." The entry used to speak `carRecapText` after a 2 h absence (in the Village: every stash item and three residents), and the microphone permission prompt — the first mic open of the session — arrived only after that and the options, while driving. Now `_carOpen` (ui-carmode.js) runs ① `STT.warmMic()` inside the gesture that opened Car Mode (native: a throwaway recognizer started and handed back on `onstart`/`onaudiostart`, the session restored on ITS `onend`, never on the abort; cloud: one `getUserMedia` whose tracks are stopped on arrival; both ride `_capture()` so the #19 handoff is the real one; resolves always, never rejects; a no-op while a listen is live), then ② the scene brief — `carSceneBrief(ws)` (helpers.js, pure): "You are at <sublocation or location>." plus the last `CAR_BRIEF_SENTENCES` = 2 sentences of the transcript's last GM entry (bookkeeping and refusal entries skipped), capped at `CAR_BRIEF_MAX_CHARS` = 320 on a word boundary — then ③ its onDone runs the ordinary post-narration loop (options, then the mic). An entry within `PREVIOUSLY_AFTER_MS` of the last turn skips the brief and goes straight to the options; the full recap stays on the spoken "previously" (`_carPreviously(true)`). **Field correction (2026-09-23):** the owner's iPhone home-screen app runs the NATIVE recognition path — the options were read aloud (the cloud path never auto-reads them) and the permission prompt came from the recognizer — so the "iOS has no SpeechRecognition" line above describes older iOS; the cloud fallback stays for where native is absent. Batteries: `dev/tests-19-audio-session.js` (16 groups), `dev/tests-19b-carmode-transport.js` (12), `dev/tests-19c-car-scene-brief.js` (5).
