### stt.js

Status: ✅ Active

Speech-to-text input: `STT` module with **two independent paths**. ① **Native** — Web Speech API (`webkitSpeechRecognition`, zero-dependency): Chrome/Edge desktop + Android Chrome; NOT Firefox; iOS Safari has NO SpeechRecognition at all. ② **Cloud fallback** — when native is absent AND an OpenAI key is on file, `MediaRecorder` captures the utterance and OpenAI transcribes it (#113 §4: `gpt-4o-mini-transcribe` primary, loud `whisper-1` fallback; `sttBiasPrompt()` roster/place/quest vocabulary on every request; WebAudio silence endpointing 1.5s/45s). **This is what makes the iPhone Safari / Car Mode path work** ([history](DOC/CLAUDE_HISTORY.md#sttjs--the-stale-doc-lesson-84)). A fully separate code section below the native one, so native behavior stays byte-identical wherever native exists; `isSupported()` gates the mic button on EITHER path. Both paths run the final transcript through **`sttCorrectNames`** (helpers.js) — roster-phonetic correction for fantasy proper nouns. Prefs: auto-send (`tnd_stt_autosend_v1`), Car Mode auto-listen (`tnd_car_autolisten_v1`, default ON) — recognition language is the constant `STT_LANG` = "en-US" (audit F7 retired `tnd_stt_lang_v1`: nothing ever wrote it, so every read returned the fallback; a real language picker brings a setter, a menu row and a line here back together). Notifies Car Mode via global `carNotify(kind,text)`, always behind a `typeof` guard. ⚠ **Transcription cost rides the PLAYER's own key** — decisive in declining LiveKit. **#77 confirm gate (v1.548):** per-utterance confidence (`sttLogEvent` ring, read via `sttLogAll()`) feeds `sttSuspicion` (helpers.js), gating the AUTO-SEND path only — Car Mode speaks "I heard: … — send it?" with spoken yes/no/redo (`parseConfirmCommand`; the confirm interceptor sits ABOVE carVoiceCommand/busy-park/<3-char gates), non-car auto-send holds + amber-flags the field; File ▸ Admin ▸ 🛡 toggle, default ON; nothing touches sessionLog/transcript until confirmed. Invented tags (the [MANA:-1] leak) are display-stripped by cleanTxt's unknown-tag catch-all

**#19 third pass (2026-09-22, v1.973) — position state is ONE push per read.** The owner's same-day result that plain narration over the car's Bluetooth stutters exactly like Car Mode's demoted the mic-cycle and transport mechanisms and pointed at the one thing every WebAudio read did on a timer regardless of mode: `_armPosState` pushed `setPositionState` every 2 s with a growing duration, and on iOS each push is a Now Playing metadata update, i.e. an AVRCP notification some head units answer by glitching their decode (Apple throttles apps that push too often — "Application exceeded audio metadata throttle limit" — and says push only when the item changes). Now `_armPosState(ctx, text)` pushes ONCE at read start — duration estimated from every queued character at the current rate (`POS_CHARS_PER_SEC` = 14 at rate 1.0), position 0, playbackRate 1, the OS extrapolates — `_clearPosState` pushes the zero state once at read end and only if something was pushed, and no timer exists. Cosmetic cost: a long read's scrubber may end early. Pinned by the `position state is ONE push per read` group in `dev/tests-19-audio-session.js`.

**#19 fourth pass (2026-09-23, v1.974) — the Car Mode entry: warm the mic, read the scene, jump to the options.** Owner ruling: "When car-mode starts, just read the current scene, and jump to options."
