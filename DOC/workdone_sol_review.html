2. Method

Nothing here was accepted on the document's authority. Each numeric claim was mapped to the command that would produce it, that command was run against the current working tree, and the output was compared to the claim. Where a claim asserted a property rather than a number — "the tag is absent from the GM's prompt documentation", "the save was never edited" — a probe was written that would fail loudly if the property were false.

The five sabotage gates temporarily mutate source files in place, so they were run strictly sequentially; running them concurrently would have interleaved mutations and corrupted the tree. git status was re-checked afterwards to confirm restoration independently of each harness's own self-report.

Three ad-hoc probes were written to the session scratchpad, not to the repository. They are reproduced verbatim in §4 so the checks can be re-run without recovering the scratch files.

4. Failure-condition probes

Three claims could have been true-by-assertion. Each was instead exercised at the condition that would break it.

Probe 1 — the W1 root cause, at the exact incident payload

The whole of W1 rests on one regex no longer matching wed inside Owed. Rather than trust the word-boundary anchors by inspection, the live WEIGHTY_REL_RE was driven with the real t1666 string and a morphology corpus in both polarities.

var engine=require("<repo>/dev/load-engine.js");engine.loadEngine();
var must=["Wife","husband","Married in Sandpoint","wedded","wedding vows","spouse","betrothed",
          "sworn oath","blood-bound","nemesis","widowed","avenged","lover","betrayal"];
var mustNot=["Owed a favor","Owed a favor collected, warming","powered","showed up","flowed",
             "crowded","screwed","wednesday? no","towed the line","allowed"];
must.forEach(function(s){console.log((WEIGHTY_REL_RE.test(s)?"OK  match   ":"FAIL nomatch")+"  "+s);});
mustNot.forEach(function(s){console.log((WEIGHTY_REL_RE.test(s)?"FAIL MATCH  ":"OK  no-match")+"  "+s);});
14/14 intended forms matched · 10/10 negatives rejected
"Owed a favor collected, warming"  →  no match
W1 REGEX OK

The exact string that corrupted the marriage now rejects, and no intended vocabulary was lost to the tightening. This is the claim in §4 of the handoff, proven at the failure condition.

Probe 2 — operator-tag containment, against the real prompt block

The handoff states the repair tag is "deliberately absent from the GM's normal prompt documentation". Since buildStateTagsDoc() is derived from TAG_TABLE, an entry could leak into the GM's instructions purely by being registered. The generated block was therefore built and searched.

["SCENE_REF","SCENE_NOT","SCENE_REVEAL","CANON_TXN_BEGIN",

OK documented  CANON_TXN_BEGIN

The hidden/visible split is real and is a property of the generated artifact, not of a comment. The operator repair tag also appears in exactly one file — tag_table.js — so there is no second surface advertising it.

Probe 3 — live-save integrity, measured on both sides of the replay

The strongest safety claim in the handoff is that campaign repair and replay never touched the player's real save. The file's size and mtime were captured before and after running the replay against it.

6. Traceability observation

This is not a defect and nothing needs undoing — it is recorded because the documents describe a history that git does not contain.

c8c37f1 is a single 24-file commit that bumps APP_VERSION from v1.598 straight to v1.601, carrying W2, W6 and W7 together. Both this handoff and CLAUDE.md narrate those as three separate releases — "W7 shipped in v1.600", "#168 W2 referential integrity (v1.599)" — but no commit is tagged, marked or bisectable at v1.599 or v1.600. Those two version markers exist only in prose.

Against the project's own rules this touches two: tight single-concern commits, and version-marker discipline as the mechanism for confirming what is actually deployed. The practical effect is narrow but real — W7 cannot be reverted, bisected or deployed independently of W6, and a field report citing "v1.600 behaviour" cannot be resolved to a tree.

Not a recommendation to rewrite history. The commit is pushed and the code is correct. The point is forward-looking: if the three workstreams are ever discussed as separable, the documents should say they shipped together as v1.601.

Reconciled. Git history was left exactly as it is; only the prose describing it changed, at the four sites that asserted a version no tree carries:

  • CLAUDE.md — the W2 and W7 contract headers now read (v1.601). That file's version tags exist so a reader can confirm what is deployed, so a marker that resolves to nothing defeats their only purpose.
  • The handoff's W7 section — "shipped in v1.600" now states it shipped in v1.601, built as the internal v1.600 stage, with the squash named.
  • The handoff's W7 gate card — "after the v1.600 markers" is now "at the W7 development stage". The 1,297-assertion checkpoint itself is real and was kept.
  • The handoff gained a standing traceability banner recording that the three staged markers exist only in prose and that the workstreams cannot be reverted or bisected apart.

Descriptions of the problem — this section, the §1 verdict row, the Fable queue entry — deliberately keep the v1.599/v1.600 strings, since removing them would erase the finding rather than fix it.

7. Limits of this check

Stated plainly so the green verdict is not read as broader than it is.

  • Focused sub-counts were not isolated. The handoff cites "28/28" focused W7 assertions, "10/10" W6, and "22 focused" W2. These live inside the 1,306-assertion aggregate, which passes; the individual sub-counts were not separately extracted and are neither confirmed nor disputed here.
  • The suite was run once, not twice. The handoff says it passed twice. One green run at 1,306 was observed; the second is uncontested but unverified.
  • The gates were trusted to define their own failure conditions. That 25 mutations are caught was verified; whether those 25 are the right 25 is a design judgement this pass did not attempt. The handoff's own §16 asks for exactly that adversarial scrutiny, and it remains open.
  • No live or browser verification. Everything here is headless. Nothing was deployed, no UI surface was rendered, and no GM turn was taken against a real API.
  • Prose claims about design intent were not adjudicated. Statements such as "detection remains conservative" or "the GM remains the writer of canon" were spot-checked against code structure but not systematically proven.

What is established: every number that could be mechanically checked was checked, and the two safety properties most likely to be assumed rather than tested — operator-tag containment and live-save integrity — were tested.
