The anti-drift stack is not broadly collapsed, but two live failures are critical. First, an explicitly non-Mokmurian scholar was silently fused into Mokmurian; the memory extractor then canonized the wrong corpse across NPC state, quest completion, chapter history, and rewards. Second, v1.595 does not detect the exact relationship overwrite it claims to fix: the unbounded token wed matches inside Owed, so the guard never queues and the same false match promotes the favor to a permanent defining memory on all four character sheets.

The surrounding pattern is consistent: low-confidence prose is allowed to cross a one-way boundary into high-authority state without referential proof. Once written, the quest, relationship, core-memory, chapter, and prompt layers reinforce each other. False audit notes add pressure and can leak into ordinary prose, but there is no evidence that they caused the identity or bond failures.

Do not treat TODO #167 as closed. Its persistence mechanism works only after a queue exists. The exact t1666 input never creates that queue, and the save also needs four-sheet core-memory repair—not only a relationship tag.

5. F1 — the wrong corpse became canon

CriticalConfirmedCross-tier

Fictional truth. At t1638 the GM says the robed tablet-reader is “Not Mokmurian himself … an old scholar-giant rather than a war-king.” t1639 repeats “not the warlord.” No later recognition or reveal reverses that evidence. At t1647 the player explicitly returns to “the scholar-giant’s neck,” and t1648 prose kills “the old scholar-giant.”

First fusion. At t1645 the GM resolves a plan to kill Mokmurian onto “Mokmurian bent over his glowing tablets.” This was not simply a player asserting that the scholar was Mokmurian; the companions proposed Mokmurian as the next target, the player accepted the plan, and the GM supplied the unsupported referent.

1 · Untracked actorObserved, targetable scholar remains anonymous and has no stable scene identity.
2 · Referential fusionPlan target “Mokmurian” is mapped onto the only visible tablet-reader.
3 · Extractor biasTrue victim is ineligible because anonymous; known Mokmurian is eligible for npcDeaths.
4 · State ratchetMokmurian becomes dead in roster and memory; chapter records the kill.
5 · ConsequencesQuest objective completes, XP pays, later dialogue reports victory.

Write mechanism. memory.js:1231–1241 auto-stamps an extracted death only for an NPC already on file. That safety rule avoids minting unknown corpses, but here it creates substitution bias: the true anonymous victim cannot be committed while Mokmurian can. fileChapter then preserves the false name in eventHistory, and the false quest objective re-injects it on later turns.

Counter-evidence checked. The relevant t1639 negative identity is available to current RAG, so “retrieval did not find it” is rejected. Quest handling is not globally broken; the false completion is downstream. The t1638 phrase “you think” allows uncertainty, but there is no intervening discovery that justifies the reversal.

Root fix: high-impact writes need referential integrity, not a stronger prompt reminder. A death, identity merge, quest completion, or reward must resolve to a present scene-entity handle. An explicit not Mokmurian constraint must quarantine a conflicting write and its downstream consequences until resolved.

Boundedness requirements

  • Scene-entity ledger: current scene only, capped (roughly 8–12), expired on scene/location transition. Reuse the existing bounded provisional-decision pattern; do not append an identity record every turn.
  • Relationships: one current bond and one current dynamic with turns; no per-change array. An unresolved integrity flag may stop nagging after a delivery budget, but it must remain visibly unresolved instead of being silently deleted.
  • Presence snapshots: current/recent absence interval per member or a small ring, not one record per turn.
  • Failure paths remain loud. A cap overflow or rejected canon commit must identify the actor/fact and preserve the raw transcript as audit evidence.

Workflow boundary

The durable fixes cross the protected drift surface: tag_table.js, api.js, memory.js, and likely data.js; game.js/state.js are ask-first. They require the project’s Fable review workflow. This report deliberately does not implement around those boundaries.

  2. Remove the false t1666 Owed defining memory from all four character sheets; a later relationship tag alone does not remove it.
  3. Treat the old scholar and Mokmurian as distinct unless the owner decides otherwise. Likely consequences: revive/unmark Mokmurian, reopen the objective, supersede the false chapter/event history, and decide whether the XP award stands.
  4. Repair Jorgenfist’s historical location/index with provenance rather than rewriting transcript text.
  5. Supersede the t1644 pronoun summary and resolve the two consumed future events.
  6. Merge the duplicate satchel only after verifying ownership/content continuity.

A raw deletion would erase the evidence that makes the repair auditable. Existing RETCON semantics cannot by themselves reverse a historical multi-tier cascade.
