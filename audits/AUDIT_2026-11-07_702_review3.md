## The tooling commits (39b60b39, 1cf0313e)

- **Can a clause be "caught" while its test ran nothing?** No. `clauseCommand` appends `--only <mustFail past the prefix>` only when the mustFail starts with the group's `only:` prefix and is longer than it; the suite's `test()` filter is a substring match on the group name, and a text that names no group exits red with "matched 0 tests", which the harness's `/matched 0 (sections|tests|checks)/` guard turns into UNOBSERVED before any attribution (meta-suite case 13). A mutation that breaks the engine's load throws before any test and prints no `FAIL #684 <name>` line, so the verdict is MISATTRIBUTED, never caught; the suite's own echo of the filter (`--only "<name>"`) cannot satisfy a mustFail because the mustFail carries the `FAIL #684 ` prefix the echo lacks. The guarded command is spawned without a shell (`dev/capture-run.js`, `spawnSync(file, args)`), so apostrophes, dashes and parentheses in a group name reach the suite verbatim.
- **Does any clause depend on a test the filter excludes?** No. A clause's verdict was always decided by whether ITS named test's FAIL line appeared: with the whole file, a mutation the named test missed but another group caught read MISATTRIBUTED; with `--only` it reads MISSED — both red. What is lost is only the side information that a mutation also broke other groups. `dev/check-684-groups-alone.js` proves every group passes alone and that each `--only <name>` runs exactly one group (a name that is a substring of another's is flagged), which is the premise the per-clause run rests on; it is green at HEAD (67, 47 s). The pane and doors batteries run the whole browser suite per clause (no `only:`), as before.
- **The guard's fragility (1cf0313e):** the regex reads the WHOLE output, so a guarded suite whose PASS line carries the phrase trips it — exactly what the meta-test's name did for the 551/475/473 batteries. The rename fixes the instance; the class remains (any future test or assertion text containing "matched 0 tests/sections/checks"). A narrower guard — the suite's own red filter line, or an exit-status-plus-marker contract — would end the class; not blocking.
- **The split:** byte-for-byte (above). The adopt and rooms batteries' 87 clauses were read one by one: each anchors a unique span of the shipped code and names the group that tests its behaviour; the two clauses the fix retired are the EQ-CLAIM mutants above (one rightly, one not — finding 3).
