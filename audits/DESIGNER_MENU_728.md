# Designer File menu and image settings (#728)

The Designer header had accumulated file, publication, model and creative controls across multiple rows (including four button rows on a 390px phone). A native File disclosure now contains New, Load, portable Save, Library, personal/catalog saves, text recovery actions, Render Options, and the existing text-model picker. Generate, AI assistant and Review remain visible. A single action table builds the file controls and retains their IDs and listeners.

Image choices come from the shared `RENDER_MODELS` registry and persist under the game's existing `RENDER_MDL_K`. Opening Render Options makes no provider call. Selecting a model updates the current Designer; the game reads the shared preference on reload. No blueprint/save schema or generation prompt changes.

Review found that `store.set` can absorb a SecurityError into memory fallback. The picker therefore reads localStorage back before reporting saved. The failure-first browser test observed the misleading `Image model saved.` message under a real Storage.prototype.setItem denial; the corrected path reports a session-only choice and failed persistence. The original setting remains on disk.
