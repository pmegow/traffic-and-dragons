# #581 — stable stash-journal identity

Status: ready pending integrated gate; isolated v1.1174 / tnd-v3-20261008a. Also addresses #527(27).

The previous mark key was the mutable campaign slot id. After stowing one of five Blasting charges and exporting the x4 sheet, a rekey caused library refresh to miss its mark and replay the same stow, leaving x3. Failure-first tests reproduced this exact condition before implementation (five of the first six probes failed).

A world-owned stashJournal has an immutable id. Born-new journals have unique ids; legacy journals derive their id from the original campId/local key so independent migrations agree. Existing marks are retained and copied once. Incoming stable marks outrank legacy aliases, including zero; only a legacy journal accepts its exact original alias. Ingest/rehome/checkpoint/bootstrap boundaries freeze legacy provenance before changing storage ids. Detached import validation precedes snapshot/global replacement. Replay arithmetic, transfer quantities, ring cap, and public presets are unchanged.

Inherited limitation: unrelated ancient journals sharing the same original campId (or local) cannot be distinguished from legitimate copies using old metadata. This patch does not claim to solve that ambiguity or reconstruct provenance already lost in earlier rekeys.
