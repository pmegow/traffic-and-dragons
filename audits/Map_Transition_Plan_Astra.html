Let the story establish the map.

A staged transition from procedural discovery to a map of established player knowledge—preserving the drawing engine, existing campaigns, and places that have already become real through play.

Build the knowledge boundary first.

My recommendation is an incremental replacement of the map’s authority, not a replacement of the renderer. Introduce one geographic knowledge model, route every player-facing map read through it, then connect narration and migrate saved campaigns. Keep the existing generator for permitted terrain, constrained geometry, and optional private preparation.

The first playable result must prove both halves of the contract: Stalgind’s unintroduced hut stays absent, while the spring, split tree, and southern arch appear when the GM introduces them—even if the party remains in the clearing.

The current failure is structural. Forest generation supplies the hut; an approximate party position opens a 100 m reveal circle; the map sends its entire sheet to the GM as authoritative geography. Meanwhile, a normal EXIT can introduce a landmark without creating anything on the drawn map. Hiding one label would leave both authority problems in place.

  1. 01Establish facts.Record what the world contains, what the party has learned, and the source of that knowledge.
  2. 02Project only that knowledge.Use one public view for the drawing, interactions, accessibility, exports, and player help.
  3. 03Preserve it over time.Keep identity, accepted placement, discoveries, and notes intact across saves, restores, and upgrades.

Included

All five existing map scales; stationary discoveries; explicit location kind; private preparation; public labels and relationships; conservative migration; version skew; prompt, identity, voice, and accessibility integration.

Kept outside this transition

A new tactical combat engine, physical line-of-sight simulation, globally replacing name-based entity IDs, multiplayer permissions, a full map editor, or another model call on every turn. The existing party knowledge is shared.

This is an XL, multi-session change across two repositories. Develop behind a campaign-format boundary; first exercise new campaigns in a development canary, then legacy copies. Enable the production default only after both paths pass. The sequence below is a dependency plan, not an estimate disguised as calendar dates.

Define exactly what “called out” means.

A meaningful feature needs a deliberate public introduction. A GM description, an explicit starting briefing, or a report delivered in play can provide it. A private blueprint entry, a generated coordinate, a nearby fog circle, or a player merely proposing an action cannot. Knowledge is recorded per attribute: seeing a hut does not reveal its name, owner, contents, or secret cellar.

Terrain is allowed to be illustrative; actionable objects are not filler. Trees can convey an established forest without each tree becoming an address. A named tree, spring, road destination, building, entrance, or identifiable ruin is a fact. Do not hide extra buildings behind the claim that they are decorative.

Knowing, seeing now, and having travelled there are independent. A remembered landmark stays on the map after leaving sight; a reported destination can appear beyond explored ground. The fog toggle may change the presentation of explored terrain, but it must never bypass public knowledge and expose private features.

A small record shape to implement against

The following is a design example, not shipped syntax. Fix the exact schema in stage 0 and pin it with fixtures before adding writers.

memory.map.geography = {
  v: 1,
  features: {
    f7: {
      container: "The Boundary Clearing",
      placeKey: null,
      facts: { kind: "arch" },
      known: {
        existence: { mode: "observed", receipt: "g12" },
        label: { value: "a stone arch", receipt: "g12" }
      }
    }
  },
  relations: [
    { from: "f7", toPlace: "The Boundary Clearing",
      kind: "bearing", value: "south", receipt: "g12" }
  ],
  receipts: {
    g12: { commit: "engine-issued-token", turn: 9, channel: "gm",
      text: "Three slabs form an arch on the southern ridge." }
  }
};

worldState.atlas.bindings.f7 = {
  zone: "existing-zone-key", anchor: [400, 390],
  precision: "schematic", source: "g12"
};

The display anchor is a layout choice, not proof of metres. A private proper name can exist in the world facts without entering known.label. A false report goes into a reported claim, not into an asserted world fact. Sources and relationship validity must be typed; the example omits private preparation and revision records for readability.

  • Identity: keep immutable name-born place keys and resolve them through locResolve. Small engine-assigned feature keys serve unvisited objects; the model refers to a scoped name or known handle, not an invented UUID. Entering a feature attaches its existing record to a place; it does not create a second landmark.
  • Merge, rename, and split: preserve feature identity, disclosures, notes, and relations. Do not merge two “Kitchen” rooms across buildings or guess allocations during a split. Register any new node field in NODE_CARRY_FIELDS; add explicit handling for references stored outside nodes.
  • Revision: distinguish world changes from knowledge corrections. Preserve a source for an old public label without continuing to display a disproved claim as fact. “Unseen” must not accidentally mean “forgotten.”
  • Preparation: generated candidates are ephemeral by default. Only an explicitly retained GM preparation becomes persistent private data. A proposal has no effect on public geometry, place identity, or future narration until deliberately adopted.

Keep authority separate in the GM prompt

Replace “the map is right” with an explicit order: accepted world facts and legitimate state changes constrain layout; public knowledge controls what can be described as already known; geometric estimates are estimates; optional private proposals are suggestions. Existing descriptions are not eternally immutable—the current stateNotes override remains legitimate world change.

The GM may see private world facts, but the public atlas digest must no longer confer canon on a generated whole sheet. Keep any proposal block separate and disabled initially. Preserve the volatile prompt boundary; no campaign-specific discovery data enters the stable prefix. buildGeoBlock is also reused by Table Talk, so use an explicit audience boundary rather than adding private content to that shared function.

Prefer an honest sketch to false precision.

The engine may choose a convenient layout for established facts, but must record which parts are illustrative. “South” provides a bearing; it does not provide 72 metres or a one-minute walk. Position confidence must govern the scale bar, travel estimates, party marker, and route claims.

  • Placement constraints first: containment, relative direction, adjacency, an explicitly known route, and a stated distance are separate typed relations. The layout must satisfy accepted constraints or leave the feature unplaced with a reason. No fallback to the nearest capital or a default village.
  • Stable anchors: adding a new landmark must not shuffle existing accepted anchors. If all constraints cannot fit, preserve the existing map and flag the conflicting relation for correction. Do not silently rotate west into north.
  • Approximate party position: a whole-sheet tie may show “somewhere in this area,” but its centre is not a vantage point. It opens no semantic discovery radius and proves no travelled path.
  • Routes: a shortest path computed over a generated network is only a drawing aid until that network is established. A straight-line fallback must not become a canonical journey, a newly explored corridor, or a travel-time claim.
  • Unavailable detail: retain an introduced place in a simple schematic or in the existing place card with “position not established.” A geometry failure must not lose the fact or stop the story.

The library boundary matters

Implement the library work in C:\Projects\TnD_Maps, then re-vendor its built distribution. Add an explicit host-controlled scene mode that supports a terrain substrate and accepted semantic objects independently. Preserve the standalone generator’s current default behaviour; the game opts into the stricter mode.

Filtering labels is insufficient. A hidden hut can still leave a footprint, clearing, doorway, shadow, hit target, or telltale fit bounds. Build the public scene from public inputs; do not draw a full private document and rely on hiding its text. Changing private candidates alone should leave the public scene unchanged. Where a secret room affects established visible geometry, keep that geometry as an accepted public constraint, not as a live dependency on hidden generation.

The current library’s area fog and ID fog cannot simply be combined, and features:{} inherits procedural defaults. The new interface needs explicit semantic visibility and per-field public names, with exploration shading applied independently. Preserve accepted outlines where they matter; decorative tree glyphs may regenerate without changing world facts.

Recipe fingerprints currently detect changed output but do not recover the old map. Resolve the known town determinism defect (#698) in the library, and independently persist the accepted semantic geometry needed to keep campaigns stable across upgrades. A stored version string alone does not pin the executing generator.

Commit disclosure with the narrated turn.

Introduce one declarative geography-event family and one operation registry—establish, disclose, relate, and correct—rather than a collection of unrelated tag side effects. Model output proposes an event; the engine supplies campaign identity, source channel, commit token, and turn. The exact tag encoding is a stage-0 decision tested against the existing parser; this plan does not assume that arbitrary JSON can safely be inserted into the current tag grammar.

Each disclosure cites a short span of the public narration, plus the attributes being disclosed. Validate bounds, supported types, scoped identity, field-level permission, and the cited span. Public labels must be supported by that span or already known. A hidden tag without its public introduction cannot publish a feature. Do not infer disclosure by scanning every noun in prose.

A source quote is evidence of occurrence, not a proof of meaning. “There is no hut,” a hypothetical hut, and a named hut do not have the same effect. Constrained declaration semantics, negative cases, prompt guidance, and reviewed model trials are required. An exact substring match alone is not the acceptance test.

  1. Prepare: classify the response as a normal narrated commit or another channel; prepare clean public text and a stable engine-issued commit token. Refusals and failed requests never receive discovery authority.
  2. Collect and preflight identity: parse geography intents into a turn-local queue. Validate any container/path claims needed by same-turn location writers before those writers mint nodes. New nested rooms resolve from an explicit accepted parent/path, not a newly generated private document. Run other canonical state mutations in their established order; do not draw maps or write knowledge inside individual tag handlers.
  3. Resolve: canonicalize containers and subjects against the accepted identity state, including same-turn arrivals and aliases. The resolver’s atlas step may consult accepted place bindings only, never private generated rooms.
  4. Admit: validate connected event groups against the public text, existing canon, and each other. Duplicate delivery is idempotent. Reject an invalid group with an attributable reason; independent valid groups may still commit. Do not roll back unrelated HP, inventory, or quest mutations.
  5. File knowledge, then place: commit valid facts and receipts, update the public projection, and reconcile geometry. If the drawing cannot place a valid discovery, preserve the discovery and use the schematic/unplaced fallback.
  6. Snapshot and publish: capture a due checkpoint only after geographic facts and bindings agree. Save the normal world/memory pair, append the narration with the same source token, and render/speak the accepted public result. Clear all turn-local intents on success, refusal, and failure.

This ordering is deliberate: today commitGmTurn calls atlasFollow, captures a due checkpoint, and only later writes the transcript entry. A disclosure handler bolted onto the later transcript write would miss that checkpoint. Prepare the source identity before mutation rather than requiring a transcript row that does not yet exist. Keep the change scoped to geographic admission, not a rewrite of the whole turn transaction.

Eight delivery stages, with a gate at each.

Stage numbers describe dependencies, not separate product modes. Keep the implementation dormant until the admission, projection, geometry, and persistence paths work together. Each stage can contain several tight commits; every game-code commit carries its version and cache bump. STAGE 1 · CANON AND KNOWLEDGE CORE

Build the single admission and read boundary.

  1. Add the focused module, a versioned sparse store, a typed operation registry, and explicit source receipts. Use null-prototype dictionaries/own-property lookup for text-keyed data, consistent with existing identity and atlas safeguards.
  2. Implement detached projections for player and GM audiences. The player projection exposes only permitted fields and public geometry inputs; neither it nor its downstream scene object retains a reachable private feature record.
  3. Handle aliases, place merges, reparenting, split allocation, and landmark-to-location attachment. Preserve the existing identity contract and room paths.
  4. Build read/migrate validation and all-or-nothing preparation for world plus memory before enabling any writer. Preserve unknown/newer data; reject unsafe writes visibly. Wire new files into every relevant script host and cache manifest.

Exit gate: deterministic unit tests cover partial attributes, private-only changes, false reports, correction, duplicate events, malformed input, merge/split, and save/load. An undisclosed proper name cannot escape through any projected field. No campaign is opted into the new format yet.

STAGE 2 · LIBRARY AND GEOMETRY

Draw a public scene without generating extra facts.

  1. In the library repository, separate terrain generation from semantic feature generation. Add an explicit scene contract for the host’s accepted features, public names, spatial constraints, and exploration shading.
  2. Support sparse scenes on all five scales. Start with schematic placement where necessary; do not require a complete procedurally filled town or dungeon before drawing a known object.
  3. Make rendering, hit testing, scene bounds, HUD labels, and export consume the same public scene. Preserve accepted anchors and door endpoints when another feature is added. Prove that undisclosed candidates do not leave geometric traces.
  4. Investigate #698 with its actual town fixtures. Pin supported-engine results and implement durable semantic anchors independently of decorative redraw. Define an explicit refusal/fallback on incompatible geometry.
  5. Build and test the library; review intentional fixture redraws; re-vendor the distribution, SHA pin, and expected version together. Never patch the game’s vendored bundle directly.

Exit gate: same public inputs produce the same semantic scene across tested engines; hidden candidates do not change player-visible output. A generic hut can be drawn without its private name, a reported spring can sit outside explored ground, and the approximate marker reveals neither. Screenshots verify actual footprints and bounds.

STAGE 3 · NARRATION, IDENTITY, AND PROMPT AUTHORITY

Make discovery an explicit part of play.

  1. Queue the declaration family through the existing tag registry and commit it at the turn boundary described above. Teach kind and placement for mid-game introductions, not just the opening.
  2. Have compatible EXIT and location events contribute scoped discovery candidates through the same admission module. A landmark does not need an arrival; an arrival does not reveal every private attribute of its node.
  3. Restrict atlasPlaceCanon and name matching to accepted geometry and scoped bindings. Preserve #693’s building-qualified room identity, including a building and room introduced in the same response. Identity-defining paths must be preflighted before location filing; the later placement pass is too late to repair a wrongly minted town-level “Kitchen.” Remove the default-village semantic fallback from the activated path.
  4. Replace the unconditional map-canon prompt with the fact/knowledge/geometry distinction. Route player-help geography through a public reader; keep legitimate GM preparation separate. Audit all callers of the shared geography builder.
  5. Implement and test refusals, retries, prose rerolls, checkpoint capture/restore, missing declarations, and conflict reporting. Normal play uses the existing GM call, with no additional automatic model request.

Exit gate: declaration without public introduction is rejected; a public introduction without movement is admitted; west does not become north; hidden geometry cannot influence identity. Real-transcript prompt and mutation diffs contain only the approved map changes. Stable-prefix checks allow only the explicitly reviewed vocabulary change, with no volatile facts entering it.

STAGE 4 · FIRST PLAYABLE SLICE

Prove the whole loop in fresh campaigns.

  1. Enable the new semantics only in disposable development campaigns. Drive the actual begin/turn/save/load paths rather than calling the projector in isolation.
  2. Recreate the Boundary Clearing: no hut, no private sheet title, no invented scale; introduce the southern arch, northern split tree, and southwest spring while stationary. Then approach one, reveal its proper name, leave, return, and reload.
  3. Cover all ten wizard starts, including coast, water, cave, and an interior whose settlement is unnamed. Missing metric or parent detail uses an honest sketch and normal narration to fill it in.
  4. Run a town → building → room → dungeon sequence with repeated room names, an authored/player-designed layout, and a secret door. Verify the same knowledge on canvas, cards, keyboard, player PNG, Table Talk, and spoken scene context.

Exit gate: a complete session works at every scale without procedural public features. All current pane navigation, party-follow, keyboard, and identity regressions remain covered. A campaign without an atlas keeps its existing behaviour and contributes no new geographic prompt block.

STAGE 5 · LEGACY MIGRATION

Reconcile the record before changing what it shows.

  1. Build a pure dry-run migrator that returns candidate state, evidence classifications, conflicts, and a human-readable diff. It must not mutate the original save or treat whole-blueprint import as disclosure.
  2. Run it on copies of every available atlas campaign, plus fixtures for old formats, ambiguous notes, missing transcripts, conflicting geometry, corrupted records, and a prior checkpoint.
  3. Review the ambiguous set with the owner/tester in one migration report. Preserve pre-migration data and stable identities. Install only a validated world/memory pair, under the new schema gates.
  4. Prove idempotent reruns, import/export, cloud/local admission, checkpoint migration, and interrupted installation. Rejected migration leaves live state byte-identical and gives a specific reason.

Exit gate: every promoted feature has evidence or an explicit legacy confirmation; every withheld candidate remains recoverable. Established visits, notes, room identities, accepted geometry, and authored layouts survive. The motivating campaign’s hut is classified explicitly, not silently deleted or automatically grandfathered as known.

STAGE 6 · CANARY AND PRODUCTION DEFAULT

Enable only the complete contract.

  1. Complete independent review of the drift-surface implementation and the library/public-scene boundary. Resolve findings before production activation.
  2. Run an integrated canary on new campaigns and reviewed migrated copies. Include desktop Chrome, the supported Node engine, and the owner’s Safari/iPhone path; inspect the rendered results rather than inferring Safari from Chromium.
  3. Rehearse old cached client access, service-worker refresh, sync conflict, a failed save, and recovery to the schematic renderer. Confirm that no recovery branch exposes a full private map.
  4. Enable the new default for new mapped campaigns; admit existing ones through the tested migration path. When migration is unresolved, preserve the old save and provide only a confirmed-location sketch until it is resolved.
  5. Record observed declaration compliance, refused conflicts, unplaced discoveries, projection time, save growth, and any redraw. Use existing local diagnostics; no new telemetry service or transcript upload.

Exit gate: the full regression suite, named sabotage cases, browser suites, migration report, and device canary all pass. Every proposed declaration in the canary is traceable to an accepted result or a visible reason for refusal. No secret leaks in the tested corpus; no unexplained changes to established geography.

STAGE 7 · REMOVE OBSOLETE AUTHORITY

End with one live system.

  1. Retire the activated path’s whole-sheet-canon prompt, procedural semantic reveal by radius, final-pointer-only discovery rule, automatic village default, and note-causes-discovery behaviour.
  2. Retire the dedicated start classifier only after the common introduction path passes its full start corpus. Keep any useful terrain classification inside the new preparation/admission boundary rather than maintaining two competing authorities.
  3. Remove temporary dual-write/probe code. Retain version readers, migrations, and legacy backup access while supported saves require them. Do not keep an invisible fallback to the old discovery logic.
  4. Update architecture and prompt/identity contracts; reconcile related TODO rows with actual shipped evidence. Close only after owner play confirms the intended behaviour.

Exit gate: one semantic writer and one public projection serve every active map. The replacement is documented, supported old saves still load safely, and all temporary feature gates have a deliberate retained or retired status.

Preserve history without inventing its provenance.

Existing campaigns contain a mixture of authored places, narrated discoveries, generated objects that became real through play, and candidates that may never have been seen. The store does not reliably record which pixels a player previously saw. Neither “generated” nor “absent from the available transcript” is a sufficient deletion rule.

Rollback must keep discoveries intact.

Use both the atlas format gate and the world save gate. ATLAS_VER protects the atlas representation; a SAVE_VER bump protects the new world/memory semantics from older clients that would otherwise ignore or overwrite them. A sheet-only version bump is unnecessary unless character sheet data changes. Validate the existing publication lock at every load, import, server adoption, and checkpoint door.

  • Old client, new save: refuse mutation and publication with the existing update-required path. Do not let an old client discard the map knowledge and sync a superficially valid world.
  • New client, old save: prepare migration off to the side. Reads used for preview must not mutate live state. Do not stamp a candidate as migrated until world, memory, and required checkpoint handling have all passed.
  • Old checkpoints: migrate the nested world/memory snapshot independently before restore, or refuse it without replacing live state. Never import the live campaign’s later discoveries into an earlier camp.
  • Cloud/local mismatch: use the existing admission and sync-conflict controls. Geography belongs to the same accepted snapshot; no separate map upload can race ahead of its narration and memory.
  • Renderer defect: switch to the public schematic or confirmed location text while retaining all facts, receipts, and anchors. Disable the defective drawing path, not the knowledge gate.
  • Release rollback: ship a compatible patch or retain a compatibility reader. Do not downgrade save data or restore an old renderer that leaks the full generated document. Restoring a pre-migration backup is an explicit recovery with a visible account of any subsequent play that would be lost.

A newer unknown geography schema should stay intact and suspend unsafe map writes; an error must not be “healed” by throwing away disclosures. The final admission policy must distinguish optional drawing damage from semantic incompatibility. Test the actual old build against the new save, not merely a mock version comparison.

Verification layers

  1. Deterministic: test every supported operation, attribute, audience, and scale. Use synthetic hidden-name canaries in every player surface. Exercise malformed objects and inherited-key names, not just normal data.
  2. Model behaviour: use a frozen corpus covering all ten starts, stationary discovery, unnamed features, reported/false information, negation, refusals, and conflicting geography. Run the current default GM configuration and supported representative alternatives. Record false acceptance and missing-declaration rates; inspect every failure. Do not claim substring validation proves semantic correctness.
  3. Rendered experience: capture the motivating desktop drawer and a narrow phone layout. Check labels, clipping, marker precision, keyboard navigation, and private geometry. Test player PNG export and spoken/context output directly.
  4. Campaign lifecycle: save, reload, export/import, alias/merge/reparent, restore a camp, retry, reroll, switch campaign, upgrade library, and open from an older client. Compare factual state as well as screenshots.
  5. Integrated canary: run at least one forest journey, one town/interior sequence, and one dungeon sequence across several save/reload cycles. Include a reviewed migrated campaign. Longer play is needed to assess accumulation and usability; a single good screenshot is not the release gate.

For each sabotage clause, name the real test section and a mustFail substring identifying its guarding assertion. An unrelated red test or a zero-section match cannot vouch for the guard. What I would build first—and when I would call it done.

The first implementation unit should be the two failing forest fixtures plus the narrow knowledge/admission seam. Use them to settle the record shape and library interface before expanding prompt vocabulary or touching live saves. The next reviewable milestone is the same clearing drawn from a public scene: no hut until introduction; three new landmarks while stationary; supported directions; no false metre scale.

Then carry that contract through rooms, doors, lifecycle paths, and migration. Do not begin with a mass deletion of generated features, a per-label allowlist, or an exception for this seed: each would leave a second route by which maps invent public facts.

  • Every meaningful public object and displayed attribute has an inspectable disclosure or explicit legacy source.
  • A feature can be learned without arrival; arrival, exploration, current visibility, and knowledge remain distinct.
  • Established geography constrains the drawing, and unknown precision is shown honestly.
  • All public surfaces agree; no private generated geometry influences public identity or context.
  • Existing campaigns retain established places, notes, identities, and accepted geometry; unresolved history remains recoverable.
  • Rerolls, checkpoints, save/load, library upgrades, device changes, and older clients respect the same contract.
  • The regression, sabotage, migration, rendering, and device gates pass; independent review is resolved; the owner confirms the experience in play.

The product change should feel simple: the player hears about a place, the map remembers it, and later play adds detail. The complexity belongs at the admission and persistence boundaries, so the GM and player are not asked to maintain two versions of the world.
