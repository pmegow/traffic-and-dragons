# Village exterior ambience — v1.931

The owner asked to roll in the reviewed recordings and explicitly selected “Implement ambience and transitions.” Their export has 26 approvals, 20 rejections and three unreviewed gravel footsteps; they confirmed that no comments were entered. The exact export and approved asset index live under ignored Audio/Reviews and Audio/approved-audio-library.json. All source files remain available, including rejected ones for reference.

The village exterior follows committed location and clock state: morning 05:00–10:00, day 10:00–18:00, light-wind evening 18:00–21:00, night 21:00–05:00. Midnight and exact boundaries are covered. Only a recorded world node with no current sublocation counts as outside. An unknown interior cannot inherit outdoor sound. The existing canonical smithy/hours rule remains intact. No game state, model prompt, tag parser or saved campaign format changed.

The old controller stopped its only source before loading another, causing the reported hard exit. It now retains at most a current and an outgoing voice. Scene changes fade for three seconds; rapid return can reuse and reverse the outgoing voice. A third change releases the oldest voice. A single abortable load/decode slot uses generation checks, so stale completions cannot play. The outgoing voice fades even if the destination fails or loads slowly; a cold/slow download can therefore leave a gap before the incoming fade. Disabled/held/paused/hidden-idle/non-gameplay/campaign changes dispose immediately. Timer retirement releases source, gain nodes and buffer references.

Each voice has separate scene-envelope and mix gains. Narration ducks both by about 10 dB without cancelling scene fades. Microphone capture clears gain automation and sets both mix gains directly to zero before recognition starts. Browser testing found that scheduling zero at currentTime alone did not yield a synchronous zero at capture start; the direct gain assignment fixes that exact failure. Voice/capture events retain the existing additive subscriptions and document car-intent contract.

Four long approved recordings are prepared as mono MP3 loops, preserving their full duration except a two-second tail/head overlap. RMS/peak level matching and provenance are in sfx/village-exterior-provenance.json. The morning rooster is retained; no claim of removal. The owner approved the source selections but did not mark these four clean, so the prepared loops still need listening acceptance. Morning/day/night are approximately 108 seconds; evening 121 seconds. Music, animals, footsteps, doors and smithing effects are catalogued as approved but are not triggered in this rollout.

## v1.934 — named outdoor sublocations (L7)

The owner's latest village save records the square as `The Village|the square`, with the village as its parent. Its exit tags are `[SUBLOCATION_LEAVE]` followed by `[SUBLOCATION:the square]`. The v1.931 adapter required both an empty sublocation and a parentless node, so this legitimate outdoor destination received no bed. The same mistake excluded the animal handler's yard. Authored exterior commons now bind through the existing canonical location resolver and must belong to the current world node. Shops, unknown rooms, other-world squares and non-village campaigns remain excluded. The recorded village root still works; no save rewrite or narration inference is involved.

Before the fix, an isolated browser using the latest save and its exact exit tags reported `exterior:false`, retained a descending fire envelope (0.796 after 600 ms), then became silent. After the fix it reported `exterior:true`, overlapped two descending/ascending envelopes, and retained only the outdoor source after three seconds. The reported instantaneous cutoff was not reproduced on this path; microphone capture and pause still intentionally silence immediately. The owner has been asked whether their exit used voice or typed/clicked input. This change does not claim to resolve a separate capture/pause issue.

Verification: two test-first engine assertions cover the saved commons, exclusions and canonical renaming; three named sabotage clauses prove those guards. The retained Chrome regression now uses the actual leave-plus-square tag sequence, checks overlap, all four clock beds, microphone silence, narration ducking, rapid reentry and release. It passed with no page errors, at most two sources and 16,081,428 decoded bytes using the v1.933 assets. Full suite: ALL GREEN, 2,181 engine assertions and the registered standalone suites. ## v1.935 — restore enabled ambience on reload

Startup read the enabled preference but only called sync, leaving unlocked false until user input even when the browser allowed autoplay. Init now attempts unlock immediately when enabled, and pageshow attempts it after pagehide disposed the controller. A resume promise blocked by autoplay may remain pending, so trusted UI interaction paths can retry resume instead of being stopped by the pending-attempt guard. Automatic startup/page-show attempts still share that guard. The existing context and controller remain singletons, no additional listener or timer is introduced, and duplicate completed resume requests do not duplicate playback. Disabled ambience remains silent and saved volume is restored.

The test-first lifecycle assertion reproduced missing startup playback and now covers allowed/blocked startup, gesture retry, disabled preferences and page restoration. Three named sabotage clauses prove those guards. The retained real Chrome test (`dev/qa-l7-reload.js`, same PLAYWRIGHT_PATH and AMBIENT_QA_URL options as transition QA) reloads with saved preferences under explicit allowed and blocked autoplay policies, checks mouse and touch activation, one loop per startup, simulated pagehide/pageshow and disabled reload. All three browser cases passed locally. Browser autoplay permission still governs whether a fresh document can play without interaction; the waiting status says "Tap anywhere to start ambience". No autoplay-policy override is used in the game.
