What changed, and why

The old generator supplied a hut that proximity fog revealed, even though the GM had never described it. The first transition removed that authority, but the 50-turn trial exposed a second problem: the GM sometimes narrated useful landmarks without emitting the new map declaration. Requiring more careful annotation alone did not reliably close that gap.

1. Read public evidence

Current, top-level MAP_REVEAL and EXIT declarations remain direct inputs. A separate model check receives only public prose spans and scoped public-known labels.

2. Validate before commit

The engine assigns source IDs and locations, checks exact quotations and closed fields, preserves stronger knowledge, and prepares all extracted additions without touching live state.

3. Draw learned places

The same turn commits the accepted knowledge. An open map refreshes without movement. Neutral pins and a readable unknown-position list avoid invented building types or precision.

EXIT declarations contribute reported destinations with unknown bearings; their descriptive notes cannot establish geometry. Extraction handles prose-only landmarks such as the birch stakes. It adds at most one utility request per narrated turn, with no history, no automatic retry, and no private blueprint, stored exit list or generated map in its input. Table Talk, rerolls, Sync and non-canonical refusals do not run this path.

If extraction fails or is cut short, the failure is reported and ordinary narration plus valid explicit declarations remain available. If the campaign changes during either asynchronous call, the stale turn is aborted. Usage stays attributed to the campaign that made the request.

Release judgment

The separate migrated copy is suitable for trying this direction now: it removes unsupported generated objects, recovers reviewed existing knowledge, and has a concrete tested path for newly narrated landmarks. Keep the broader default opt-in while collecting ordinary play evidence. This closes the specific discovery and migration gaps without claiming the entire map transition is finished.

Remaining limits include model omissions and mistaken relevance, changing descriptive names, no inferred synonyms or location links, no precise distance or scale, no general reconstruction of historical discovery, and no measured extraction compliance over a new long campaign. The original save’s checkpoint metadata contains no nested snapshot; migration cannot reconstruct that missing content.

Admission and privacy contract
  • Balanced top-level public prose only: all bracket subtrees, nested private content and canon transaction bodies are excluded. Unsafe movement scope refuses before geographic writers.
  • Raw response ≤60,000 characters; public text ≤16,000; ≤64 spans and 32 scopes. Known public context is capped at 128 features with an explicit omitted count.
  • Closed JSON: ≤16 records, exact source ID, literal label and quotation, observed/reported mode, bounded bearing evidence, and an overflow flag. Unknown fields, cut completion, malformed JSON and source changes refuse.
  • Locations come from engine source offsets. Proposals cannot supply containers, coordinates, ownership, classification, node identities or private data.
  • Explicit MAP declarations take precedence. Exact scoped labels reuse stable handles; canonical ambiguity refuses. Known bearings and observed status cannot be weakened; a reported EXIT can advance when public observation supports it.
  • The entire extraction candidate prepares before installation. Explicit and extracted batches are independent: valid explicit knowledge survives extraction failure, and unrelated sourced extraction may survive an explicit bearing contradiction. Unsafe or malformed source blocks extraction.
  • No private-map fallback, extra repair call, silent eviction or prose rewriting. Stale campaign responses cannot commit into a replacement campaign.
